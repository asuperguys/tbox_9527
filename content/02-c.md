### 指针与数组的区别
**一句话要点**：数组名在多数表达式中退化为指向首元素的指针，但 sizeof(数组名) 得到整个数组大小；指针是变量可重新赋值，数组名不是左值。

**面试怎么问**：sizeof(arr) 和 sizeof(ptr) 分别是多少？数组作为函数参数为什么退化为指针？怎么在函数里正确拿到数组长度？

**标准回答 · 开场 30 秒（先给结论）**：
> 数组和指针最大的区别是：数组是一块连续内存，不是一个变量；指针是一个存放地址的变量。数组名在大多数表达式里会退化成指向首元素的指针，但有两个例外——作为 sizeof 的操作数和作为 & 的操作数时，它保持数组身份。所以 sizeof(arr) 是整个数组的大小，而 sizeof(p) 只是指针大小。

**展开 1 · 为什么函数参数会退化（考原理）**：
> 函数参数写成 int a[] 本质就是 int *a。因为 C 传参是值传递，不可能把整个数组拷贝进栈，只能把首元素地址传过去，所以形参自动退化成指针——这也意味着函数内部拿不到数组长度，必须额外传一个 len。

**展开 2 · 怎么正确拿长度（考实践）**：
> 在定义数组的同一个作用域里，可以用 sizeof(arr)/sizeof(arr[0]) 拿到元素个数；但传进函数后不行，只能靠调用方把长度一起传进来，比如 print_arr(arr, sizeof(arr)/sizeof(arr[0]))。

**收尾 · 加分项（数组名不是左值）**：
> 数组名不是左值，arr++、arr = p 都是非法的，而指针可以重新赋值。这正好说明数组名不是指针变量，它只是这块内存的标识。被追问"什么叫左值"时答：能出现在赋值号左边、有地址可被赋值的表达式。

**用例 / 示例**：
```c
int arr[10];        // sizeof(arr) == 40（10 × 4）
int *p = arr;       // sizeof(p) == 8（64 位平台）

void f(int a[]) {   // 等价于 void f(int *a)，形参退化为指针
    sizeof(a);      // 8：拿不到长度，必须另传 len
}

// 正确的传数组方式：指针 + 长度
void print_arr(int a[], size_t len)
{
    for (size_t i = 0; i < len; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
}
print_arr(arr, sizeof(arr) / sizeof(arr[0]));   // 定义处才能这样算长度

// 注意：arr++ 非法（数组名不是左值），p++ 合法
```

**面试官可能追问的 3 个坑（提前备好）**：

| 追问 | 怎么答 |
|---|---|
| &arr 和 arr 的区别？ | arr 退化成 int*（指向首元素），&arr 是 int(*)[10]（指向整个数组）。&arr + 1 跳过 40 字节，arr + 1 只跳 4 字节。 |
| 二维数组 int a[3][4] 退化为什么？ | 退化为 int (*)[4]（指向含 4 个 int 的数组的指针），不是 int**。 |
| sizeof(arr)/sizeof(arr[0]) 在函数里为什么错？ | 形参已退化，sizeof(a) 是 8 不是数组大小，除出来是 2 而不是 10——最常见的笔试陷阱题。 |

**关联项目**：GNSS 固件升级（串口接收缓冲的指针操作）、通用基础

### const / volatile / static / extern 的作用
**一句话要点**：const 限定只读、编译期检查；volatile 禁止编译器优化、每次都从内存读取，用于硬件寄存器与中断/多线程共享变量；static 修饰局部变量（只初始化一次）或把符号限定在本文件；extern 声明跨文件符号。
**面试怎么问**：volatile 到底解决了什么问题？const 和 volatile 能同时修饰一个变量吗？（能，如只读硬件寄存器）static 局部变量和普通局部变量的区别？
**用例 / 示例**：
```c
const int *p;      // p 指向的内容只读
int *const q;      // q 本身不可重新赋值

// volatile：硬件状态寄存器，必须每次重新读
#define REG_STATUS (*(volatile uint32_t *)0x40001000)
while (REG_STATUS & 0x01) {
    /* 等待硬件置位；若无 volatile，编译器可能只读一次 */
}

// static 局部变量：只初始化一次，跨函数调用保持
int next_seq(void)
{
    static uint16_t seq = 0;   // 首次进入初始化，之后保持
    return seq++;
}

// extern：声明在别的 .c 中定义的全局变量
extern int g_tbox_uptime_s;
```
**关联项目**：GNSS 固件升级（寄存器/中断标志）、通用基础

### 函数指针与回调
**一句话要点**：函数名即地址，函数指针可做回调（异步完成通知）和表驱动分发（命令表、状态机），是 C 语言实现解耦的核心手段。
**面试怎么问**：回调函数怎么实现？函数指针数组在嵌入式里有什么典型用途？函数指针的 typedef 怎么写？
**用例 / 示例**：
```c
typedef int (*cmd_handler_t)(const char *args);

int cmd_pcc_start(const char *args);   // 指令处理函数
int cmd_pcc_stop(const char *args);
int cmd_pcc_status(const char *args);

enum { CMD_PCC_START, CMD_PCC_STOP, CMD_PCC_STATUS, CMD_MAX };

// 表驱动：用下标代替一长串 if/else
static cmd_handler_t cmd_table[CMD_MAX] = {
    [CMD_PCC_START]  = cmd_pcc_start,
    [CMD_PCC_STOP]   = cmd_pcc_stop,
    [CMD_PCC_STATUS] = cmd_pcc_status,
};

int dispatch(int cmd_id, const char *args)
{
    if (cmd_id < 0 || cmd_id >= CMD_MAX) {
        return -1;                    // 边界：命令号越界
    }
    cmd_handler_t fn = cmd_table[cmd_id];
    if (fn == NULL) return -2;        // 边界：未注册
    return fn(args);                  // 回调调用
}
```
**关联项目**：云公交一体机（指令分发）、OTA 排查支持（升级流程回调）

### 宏 vs 函数、#pragma pack、头文件防重复包含
**一句话要点**：宏在预处理期做文本替换、无类型检查，参数必须加括号防副作用；函数有类型检查但调用有栈开销；#pragma pack 控制结构体对齐，用于协议报文；头文件用 #ifndef/#define/#endif 或 #pragma once 防重复包含。
**面试怎么问**：MAX 宏为什么每个参数都要加括号？#pragma pack(1) 用在什么场景？头文件重复包含会有什么后果？
**用例 / 示例**：
```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))   // 参数必须加括号

int x = 1;
int r = MAX(x++, 3);
// 展开为 ((x++) > (3) ? (x++) : (3))，x 被自增两次 —— 宏副作用坑

// #pragma pack：网络/总线协议报文按 1 字节紧凑排列
#pragma pack(1)
typedef struct {
    uint8_t  head;          // 帧头
    uint16_t len;           // 载荷长度
    uint8_t  payload[64];   // 载荷
    uint8_t  crc;           // 校验
} frame_t;                  // sizeof == 68，无填充字节
#pragma pack()
```
```c
// 头文件防重复包含（两种写法选其一）
#ifndef __TBOX_FRAME_H__
#define __TBOX_FRAME_H__
/* 声明内容 */
#endif
// 或：#pragma once
```

### 结构体内存对齐与大小端
**一句话要点**：结构体成员按自身对齐数放置，总大小是最大对齐数的整数倍，中间有填充字节；大小端指多字节数据在内存中的字节序，x86/ARM 默认小端、网络字节序是大端，协议收发必须显式转换。
**面试怎么问**：下面这个结构体 sizeof 是多少？怎么判断当前平台大小端？CAN/网络报文解析要注意什么？
**用例 / 示例**：
```c
struct s1 {            // 默认 4 字节对齐
    char  a;           // offset 0
    int   b;           // offset 4（跳过 3 字节填充）
    char  c;           // offset 8
};                     // sizeof == 12（补齐到 4 的整数倍）

// 判断大小端：看低地址存的是低字节还是高字节
int is_little_endian(void)
{
    uint16_t x = 0x1234;
    return *(uint8_t *)&x == 0x34;   // 小端：0x34 在低地址
}

// 协议收发统一用 htons/htonl 转网络序（大端）
uint16_t n = htons(len);             // 主机序 -> 网络序
uint16_t len = ntohs(n);             // 网络序 -> 主机序
```
**关联项目**：云公交一体机（协议报文解析）、主动安全系统（CAN 信号解析）

### 位操作（置位/清位/翻转/统计 1 的个数）
**一句话要点**：位操作是嵌入式寄存器配置和标志管理的基础：| 置位、&~ 清位、^ 翻转、& 判断；统计 1 的个数用 Kernighan 算法 x &= (x-1)，循环次数等于 1 的个数。
**面试怎么问**：把第 n 位置 1 / 清零怎么写？统计一个 uint32 里 1 的个数？判断一个数是不是 2 的幂？
**用例 / 示例**：
```c
#define BIT(n) (1u << (n))

uint32_t reg = 0;
reg |= BIT(3);          // 置位第 3 位
reg &= ~BIT(3);         // 清位第 3 位
reg ^= BIT(3);          // 翻转第 3 位
if (reg & BIT(3)) { }   // 判断第 3 位是否为 1

// 统计 1 的个数：每次清除最低位的 1，循环次数 = 1 的个数
int popcount(uint32_t x)
{
    int cnt = 0;
    while (x) {
        x &= (x - 1);
        cnt++;
    }
    return cnt;
}

// 判断 2 的幂：只有 1 个 1，且 x > 0
int is_pow2(uint32_t x)
{
    return x && ((x & (x - 1)) == 0);
}
```
**关联项目**：GNSS 固件升级（FLASH 寄存器配置）、主动安全系统（状态标志位）

### 单链表：反转/找环/合并两个有序链表
**一句话要点**：反转用三指针迭代（先存后继再改指向）；找环用快慢指针（快 2 步慢 1 步，相遇即有环）；合并有序链表用哨兵节点避免处理头节点特例。
**面试怎么问**：手写链表反转；怎么判断链表有环并找出环入口；合并两个有序链表；注意哪些边界条件（空链表、单节点、环）？
**用例 / 示例**：
```c
typedef struct node {
    int val;
    struct node *next;
} node_t;

// 反转：三指针迭代
node_t *reverse(node_t *head)
{
    node_t *prev = NULL, *cur = head;
    while (cur) {
        node_t *next = cur->next;   // 先保存后继，防止断链
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    return prev;                    // 新链表头
}

// 找环：快慢指针
int has_cycle(node_t *head)
{
    node_t *slow = head, *fast = head;
    while (fast && fast->next) {    // 边界：空表、单节点
        slow = slow->next;          // 1 步
        fast = fast->next->next;    // 2 步
        if (slow == fast) return 1; // 相遇即有环
    }
    return 0;
}

// 合并两个有序链表：哨兵节点省去头节点特判
node_t *merge(node_t *a, node_t *b)
{
    node_t dummy = {0, NULL};       // 哨兵，栈上临时节点
    node_t *tail = &dummy;
    while (a && b) {
        if (a->val <= b->val) { tail->next = a; a = a->next; }
        else                  { tail->next = b; b = b->next; }
        tail = tail->next;
    }
    tail->next = a ? a : b;         // 接上剩余部分
    return dummy.next;
}
```
**关联项目**：通用基础（高频手写题）、云公交一体机（任务链表管理）

### 环形缓冲区（加锁版与无锁版思路）
**一句话要点**：环形缓冲区用 head/tail 指针 + 模运算实现 FIFO，留一个空位区分空/满：(tail+1)%size==head 为满、tail==head 为空；多线程用互斥锁，单生产者单消费者（SPSC）可无锁：先写数据再更新指针，配合内存屏障防乱序。
**面试怎么问**：环形缓冲怎么判空判满？容量为什么是 size-1？SPSC 无锁的关键点是什么？
**用例 / 示例**：
```c
typedef struct {
    uint8_t *buf;
    int      size;
    int      head;          // 读位置
    int      tail;          // 写位置
    pthread_mutex_t lock;
} ring_t;

// 写入（加锁版）
int ring_push(ring_t *r, uint8_t data)
{
    pthread_mutex_lock(&r->lock);
    int next = (r->tail + 1) % r->size;   // 留一格区分空/满
    if (next == r->head) {                // 满：返回失败
        pthread_mutex_unlock(&r->lock);
        return -1;
    }
    r->buf[r->tail] = data;   // 先写数据
    r->tail = next;           // 再更新写指针
    pthread_mutex_unlock(&r->lock);
    return 0;
}

// 读取（对称实现）。无锁 SPSC 思路：
// 写者：先写 buf[tail]，再更新 tail（写屏障保证顺序可见）
// 读者：先读 head，再读 buf[head]（读屏障）
// 各自只操作自己的指针，天然互不竞争
```
**关联项目**：GNSS 固件升级（串口接收 FIFO）、主动安全系统（CAN 报文接收队列）

### 栈与队列的实现
**一句话要点**：栈是 LIFO（后进先出），可用数组或链表实现；队列是 FIFO，顺序队列有假溢出问题，用循环队列或链表实现；链式实现天然动态扩容，但要处理内存分配失败。
**面试怎么问**：数组实现队列为什么会假溢出？循环队列怎么判空判满？用两个栈实现队列怎么搞？
**用例 / 示例**：
```c
// 链式栈：头插法，无需判满
typedef struct node { int val; struct node *next; } node_t;

typedef struct { node_t *top; } stack_t;

int stack_push(stack_t *s, int v)
{
    node_t *n = malloc(sizeof(node_t));
    if (n == NULL) return -1;      // 边界：内存不足
    n->val = v;
    n->next = s->top;
    s->top = n;
    return 0;
}

int stack_pop(stack_t *s, int *out)
{
    if (s->top == NULL) return -1; // 边界：栈空
    node_t *n = s->top;
    *out = n->val;
    s->top = n->next;
    free(n);
    return 0;
}
// 循环队列：head==tail 为空，(tail+1)%cap==head 为满，
// 与环形缓冲区同一套思路，容量为 cap-1
```
**关联项目**：云公交一体机（任务/消息队列）、通用基础（手写题）

### 字符串函数 strlen/strcpy/memcpy/memmove 与安全版本
**一句话要点**：strlen 遍历到 '\0' 不含结束符；strcpy 不检查目标空间且遇 '\0' 停止，不安全；strncpy 在源更长时不补 '\0'，需手动补；memcpy 按字节复制但**不处理内存重叠**，memmove 处理重叠（按方向复制）；生产代码用 snprintf/strlcpy 等安全版本。
**面试怎么问**：memcpy 和 memmove 的区别？strncpy 的坑是什么？怎么实现一个 memmove？
**用例 / 示例**：
```c
// memmove 处理重叠：dst < src 从前往后，否则从后往前
void *my_memmove(void *dst, const void *src, size_t n)
{
    char *d = dst;
    const char *s = src;
    if (d == s || n == 0) return dst;        // 边界
    if (d < s) {                             // 从前往后
        for (size_t i = 0; i < n; i++) d[i] = s[i];
    } else {                                 // 从后往前
        for (size_t i = n; i > 0; i--) d[i - 1] = s[i - 1];
    }
    return dst;
}

char buf[16];
strncpy(buf, "hello", sizeof(buf) - 1);
buf[sizeof(buf) - 1] = '\0';   // strncpy 可能不带结束符，手动补
// 生产建议：snprintf(buf, sizeof(buf), "%s", src);
```
**关联项目**：OTA 排查支持（日志/版本字符串解析）、市场问题分析eMMC-eSIM

### 编译链接过程与静态库/动态库
**一句话要点**：编译分四步：预处理（宏展开/头文件包含）→ 编译（生成目标文件 .o）→ 汇编 → 链接（符号解析 + 重定位、合并段）；静态库 .a 链接时拷入可执行文件，动态库 .so 运行时加载、多进程共享省内存，但存在运行时依赖和符号冲突问题。
**面试怎么问**：编译链接的完整过程？静态库和动态库的区别与选择？undefined reference 怎么排查？
**用例 / 示例**：
```bash
# 四步手动执行（gcc 也可一步完成）
gcc -E main.c -o main.i          # 预处理
gcc -S main.i -o main.s          # 编译成汇编
gcc -c main.s -o main.o          # 汇编成目标文件
gcc main.o -L./lib -lprotocol -o app   # 链接：-L 库目录，-l 库名（去 lib 前缀）

# 静态库：ar 打包
gcc -c protocol.c -o protocol.o
ar rcs libprotocol.a protocol.o

gcc -fPIC -shared -o libprotocol.so protocol.c
```

### 原码、反码、补码
**一句话要点**：正数三码相同；负数反码 = 原码除符号位外取反、补码 = 反码 + 1；CPU 用补码存负数，把减法统一成加法、0 只有一种表示，且能多表示一个 -128。
**面试怎么问**：-5 的补码是多少？为什么计算机用补码表示负数？0xFFFFFFFF 是无符号 4294967295 还是有符号 -1？
**用例 / 示例**：
```c

// 原码：1000 0101（最高位符号位 1 + 数值位 000 0101）
// 反码：1111 1010（符号位不变，数值位取反）
// 补码：1111 1011（反码 + 1）

int8_t a = -5;       // 内存里实际存 0xFB（补码）
uint8_t b = 0xFB;    // 同一字节：按有符号解释是 -5，按无符号解释是 251

// 为什么用补码：5 + (-5) = 0000 0101 + 1111 1011 = 1 0000 0000
// 溢出位丢掉得 0，减法变成了加法，硬件只需要加法器
// 8 位范围：-128（0x80）~ +127（0x7F）；0 只有全 0 一种编码（原码有 +0/-0 两种）
```

### 结构体 vs 共用体 union 对比（sizeof 计算与类型转换）
**一句话要点**：结构体成员共存、sizeof ≈ 成员和 + 填充字节；union 成员共享同一块内存、sizeof = 最大成员（含对齐）；union 的典型用途是协议解析和类型转换——把一个变量的位模式按另一种类型读写，零拷贝。


### 数组指针 int (*p)[N] 与指针数组 int *p[N]
**一句话要点**：指针数组是"数组、元素是指针"（int *p[N]，先结合数组）；数组指针是"指针、指向含 N 个 int 的数组"（int (*p)[N]，先结合指针）；二维数组名传给函数时形参写 int (*p)[N]。


### 函数调用约定 __stdcall 与 __cdecl
**一句话要点**：两者参数都从右往左压栈；区别在谁清理栈：__cdecl 由调用方清理（C 默认、支持可变参数 printf），__stdcall 由被调函数清理（代码省、Win32 API 常用、不支持变参）。
**面试怎么问**：__cdecl 和 __stdcall 有什么区别？为什么 printf 这类可变参数函数不能用 __stdcall？
**用例 / 示例**：
```c
// Windows 平台写法（Linux 默认 __cdecl，一般不用写）
int __cdecl   sum_c(int a, int b);   // 调用方平衡栈
int __stdcall sum_s(int a, int b);   // 被调函数平衡栈

// 压栈顺序：先压 b 再压 a（从右往左），两种约定相同
// 可变参数：只有调用方知道参数个数，必须由调用方清栈，
// 所以 printf 只能是 __cdecl，__stdcall 函数不支持 ... 参数
// __stdcall 在函数返回处用 ret n 一条指令回收参数栈，代码更紧凑；
// __cdecl 每次调用后调用方 add esp 清栈，支持变参
// 补充：x86 才讲究这套栈约定；ARM/AAPCS 前 4 个参数走寄存器
```

### main 函数参数 argc/argv
**一句话要点**：argc 是命令行参数个数（含程序名本身），argv 是字符串参数数组，argv[0] 恒为程序名；参数全是字符串，数字要 atoi/strtol 转换，遍历时先判边界防缺参越界。
**面试怎么问**：argc 的值是多少？argv[0] 是什么？怎么给程序传配置参数？
**用例 / 示例**：
```c
// 执行：./app -p /dev/ttyUSB0 -b 115200
int main(int argc, char *argv[])
{
    // argc == 5（程序名 + 4 个参数）
    // argv[0] = "./app"        argv[1] = "-p"
    // argv[2] = "/dev/ttyUSB0"  argv[3] = "-b"
    // argv[4] = "115200"
    for (int i = 1; i < argc; i++) {
        if (strcmp(argv[i], "-p") == 0 && i + 1 < argc) {
            const char *dev = argv[++i];   // 串口设备名
        } else if (strcmp(argv[i], "-b") == 0 && i + 1 < argc) {
            int baud = atoi(argv[++i]);    // 波特率，字符串转数字
        }
    }
    return 0;
}
// 注意：访问 argv[i+1] 前必须判 i+1 < argc，防止缺参时越界
```

### sizeof 与 strlen 的区别
**一句话要点**：sizeof 是编译期运算符，算类型/变量占用的字节数，字符串数组含 '\0'；strlen 是运行期函数，遍历到 '\0' 才停、不含结束符；对指针做 sizeof 只得到指针大小，拿不到字符串长度。
**面试怎么问**：char s[] = "Hello"; sizeof(s) 和 strlen(s) 分别是多少？为什么 sizeof(数组参数) 会出错？
**用例 / 示例**：
```c

strlen(s)  == 5          // 运行期数到 '\0' 为止，不含结束符

char *p = s;
sizeof(p)  == 4/8        // 是指针大小，不是字符串长度！
strlen(p)  == 5          // 仍然正确

void f(char a[])         // 形参退化成指针
{
    sizeof(a) == 8;      // 拿不到数组长度，必须另传 len
}
// 结论：要"缓冲区大小"用 sizeof（编译期、安全）；
// 要"字符串有效长度"用 strlen（运行期，前提是有 '\0'）
```

### offsetof 宏与结构体成员偏移计算
**一句话要点**：offsetof(type, member) 在 <stddef.h> 中定义，编译期算出成员相对结构体起始的偏移字节数，经典实现是 ((size_t)&((type *)0)->member)——利用"0 地址强转后取成员地址"的编译期技巧。

```c

    uint8_t  head;      // offset 0
    uint16_t len;       // offset 2（对齐到 2 字节边界）
    uint32_t crc;       // offset 4
} frame_t;

offsetof(frame_t, len)  == 2
offsetof(frame_t, crc)  == 4
sizeof(frame_t)         == 8

// 原理：把 0 强转成 frame_t*，再取成员地址转 size_t——
// 编译期常量，不会真的访问 0 地址
#define MY_OFFSETOF(t, m) ((size_t)&(((t *)0)->m))

// 用途：协议解析时按偏移定位字段（配合 memcpy 避免对齐问题）

uint32_t crc;
memcpy(&crc, raw + offsetof(frame_t, crc), sizeof(crc));
```

### volatile 能保证线程安全吗
**一句话要点**：不能。volatile 只保证"每次从内存读、不做缓存优化"，不保证读-改-写的原子性；count++ 是三步操作，多线程并发时 volatile 照样丢更新，必须用原子操作或互斥锁。
**面试怎么问**：volatile 修饰的变量多线程自增安全吗？volatile 和原子操作、锁的区别？
**用例 / 示例**：
```c
volatile int count = 0;

void *worker(void *arg)      // 两个线程同时跑
{
    for (int i = 0; i < 100000; i++)
        count++;             // 非原子：读 -> 加 1 -> 写，三步可被打断
    return NULL;
}
// 两个线程各加 10 万次，结果经常 < 20 万：
// A 读到 100 还没写回，B 也读到 100，都写 101，一次更新丢失

// 正确做法一：原子操作（C11）
#include <stdatomic.h>
atomic_int acnt = 0;
atomic_fetch_add(&acnt, 1);

// 正确做法二：互斥锁
pthread_mutex_lock(&mtx);
count++;
pthread_mutex_unlock(&mtx);

// volatile 的正确用法：共享标志位（读写本身原子，不需要三步）
volatile int g_stop = 0;     // 主线程置 1 通知工作线程退出，无需锁
```
**关联项目**：主动安全系统（多线程共享标志）、通用基础

### const 与 #define 的区别
**一句话要点**：#define 是预处理期纯文本替换、无类型检查、无作用域、不占内存、调试器看不到；const 是编译期变量、有类型检查、有作用域、可调试；类型安全用 const/enum，条件编译和简单数值宏用 #define。
**面试怎么问**：const 和 #define 的区别？为什么推荐用 const 定义常量？#define 有什么坑？
**用例 / 示例**：
```c
#define MAX_LEN 100       // 预处理期替换成 100；无类型；全局可见（无作用域）
const int max_len = 100;  // 编译期常量；有 int 类型；作用域受声明位置限制

// 区别清单：
// 1. 时机：#define 预处理期，const 编译期
// 2. 类型检查：const 有（如 const int* 不能赋给 int*），宏没有
// 3. 调试：const 是真实符号，gdb 能 print；宏在调试器里看不到
// 4. 存储：宏不占存储；const 视编译策略可能进 .rodata 只读段
// 5. 作用域：#define 无作用域概念，容易污染命名空间
// 6. 报错体验：宏展开后报错信息难懂

// 实践：数组大小、协议常量用 const 或 enum
enum { PROTO_VER = 3 };   // enum 也是编译期常量、有类型，常用
// #define 留给条件编译（#ifdef）和简单表达式
```
**关联项目**：通用基础、云公交一体机（协议常量定义规范）

### main 调用之前系统做了什么
**一句话要点**：程序入口不是 main：启动代码（CRT/crt0）先初始化栈指针、清零 .bss、把 .data 拷到 RAM、准备 argc/argv 和标准 I/O，才调用 main；嵌入式裸机对应汇编启动文件（配时钟/内存后跳 main）。
**面试怎么问**：main 之前系统做了什么？为什么 .bss 不用烧进固件？嵌入式启动文件和 PC 的 CRT 对应关系？
**用例 / 示例**：
```c
// PC/Linux 可执行文件启动流程（crt0 / libc 启动代码）：
// 1. 内核加载可执行文件，分配虚拟地址空间
// 2. 入口 _start 开始执行（汇编，不是 main）
// 3. 初始化栈指针、环境变量、命令行参数
// 4. 清零 .bss（未初始化全局段：不占文件体积，运行时占 RAM）
// 5. 把 .data（已初始化全局变量）从文件拷到 RAM
// 6. C 库初始化：stdio 缓冲、malloc 堆、atexit 注册
// 7. 调用 main(argc, argv)；main 返回后调 exit() 做清理

// 嵌入式裸机对应（ARM startup.s）：
// Reset_Handler：关中断 -> 初始化栈 -> 拷 .data -> 清零 .bss
//              -> 配时钟/外设 -> 跳 main
// 这就是"全局变量在 main 前就有初值、局部变量没有"的原因
```
**关联项目**：GNSS 固件升级（固件入口/启动流程）、通用基础

### 防御性编程
**一句话要点**：假设一切外部输入都可能是错的：入口校验参数、用长度而不是信任内容、每次系统调用/内存申请检查返回值、用断言抓住不变量、错误路径也要清理资源；宁可明确报错也不静默吞错。
**面试怎么问**：你怎么保证协议解析代码不会越界？函数入口一般要检查什么？assert 和发布代码的关系？
**用例 / 示例**：
```c
int parse_frame(const uint8_t *data, size_t len, frame_t *out)
{
    // 1. 参数校验：空指针、长度下限
    if (data == NULL || out == NULL || len < 4) return -EINVAL;
    // 2. 协议级边界：长度字段必须与缓冲一致（防越界读）
    uint16_t payload_len = (data[1] << 8) | data[2];
    if ((size_t)payload_len + 4 > len) return -EMSGSIZE;
    // 3. 业务不变量用断言（调试期抓 bug，发布版可关）
    assert(payload_len <= MAX_PAYLOAD);
    // 4. 返回值处理：内部调用也要检查
    if (memcpy(out->payload, data + 4, payload_len) == NULL) {
        return -EFAULT;
    }
    return 0;   // 成功路径
}
// 总原则：所有外部输入（网络、CAN、串口、文件）一律不可信；
// open/read/write 等系统调用返回值必须检查；
// 错误路径释放已申请的资源（见内存泄漏小节）
```
**关联项目**：主动安全系统（安全关键代码）、GNSS 固件升级（升级包校验）

### strcpy vs memcpy 与手撕 memcpy（补充）
**一句话要点**：strcpy 按 '\0' 停止、不知道目标容量；memcpy 按字节数拷贝、不关心内容；两者都不处理内存重叠，重叠必须用 memmove（实现见上文字符串函数小节）；手撕 memcpy 按字节循环拷贝即可。
**面试怎么问**：strcpy 和 memcpy 的区别？memcpy 遇到重叠会怎样？手写 memcpy。
**用例 / 示例**：
```c
// 手写 memcpy：按字节拷贝（朴素版，不处理重叠）
void *my_memcpy(void *dst, const void *src, size_t n)
{
    if (dst == NULL || src == NULL || n == 0) return dst;   // 边界
    char *d = dst;
    const char *s = src;
    for (size_t i = 0; i < n; i++) {
        d[i] = s[i];
    }
    return dst;
}

// 区别：
// strcpy(dst, src)   —— 按 '\0' 停止，无长度参数，目标越界风险高
// memcpy(dst, src, n) —— 按 n 字节拷贝，不关心内容，需要长度
// 重叠场景：memcpy(dst, dst+3, 10) 会互相覆盖出错，
// 必须用 memmove（按方向复制，见上文"字符串函数"小节）
// 优化点：数据量大时按 4/8 字节（字）拷贝提高效率，字节版逻辑最清晰
```
**关联项目**：通用基础（高频手写题）、市场问题分析eMMC-eSIM

### 寄存器位操作实战：读-改-写与多比特配置
**一句话要点**：置位 REG |= (1<<n)、清位 REG &= ~(1<<n)、翻转 REG ^= (1<<n)；但"读-改-写"非原子，中断/多核并发操作同一寄存器会丢修改，需关中断或用原子指令；配置相邻多位用"先清掩码再或值"一次完成。
**面试怎么问**：配置寄存器某几位为指定值怎么写？读-改-写为什么有风险？中断里操作寄存器要注意什么？
**用例 / 示例**：
```c
#define REG (*(volatile uint32_t *)0x40001000)

REG |= (1u << 3);         // 置位第 3 位，其余位不动
REG &= ~(1u << 3);        // 清位第 3 位，其余位不动
REG ^= (1u << 3);         // 翻转第 3 位
if (REG & (1u << 3)) {}   // 判断第 3 位

// 配置多个相邻位（bit4-6 写 0b101）：先清掩码，再或值，一次完成
REG = (REG & ~(0x7u << 4)) | (0x5u << 4);

// 读-改-写（RMW）非原子风险：
// 中断里改了 bit3，主程序 RMW 读到的可能是旧值，写回时把中断的修改冲掉
// 对策 1：关中断再操作
__disable_irq();
REG |= (1u << 3);
__enable_irq();
// 对策 2：写 1 清标志这类"只写"寄存器直接赋值，不做 RMW，如
// IRQ_CLEAR = (1u << 3);   // 不读不改，天然无竞争
```
**关联项目**：GNSS 固件升级（FLASH/串口寄存器）、主动安全系统（CAN 控制器配置）

### 全局变量 vs 局部变量
**一句话要点**：全局变量存全局数据区（.data/.bss）、默认自动清零、生命周期是整个程序、可被多个函数访问；局部变量存栈、不自动初始化（随机值）、生命周期只在函数执行期间、仅函数/代码块内可见。
**面试怎么问**：全局变量和局部变量分别存在哪个区？没初始化的全局变量为什么是 0、局部变量却是随机值？全局变量有哪些缺点？
**用例 / 示例**：
```c
int g_cnt;             // 全局变量 -> .bss，启动代码自动清零（== 0）
int g_ver = 3;         // 全局变量 -> .data，有初值
static int g_internal; // 全局 static：存全局区，但只在本文件可见

int calc(int x)
{
    int local = x;     // 局部变量 -> 栈，不自动初始化（随机值，必须赋初值）
    static int calls = 0;   // static 局部：存全局区，只初始化一次，跨调用保持
    calls++;
    return local + calls;
}

// 对比要点：
// 存储位置：全局 -> .data/.bss；局部 -> 栈
// 默认初始化：全局自动清零（.bss 由启动代码清零）；局部不初始化
// 生命周期：全局整个程序；局部仅函数执行期间，函数返回即失效
// 作用域：全局可被所有函数访问（extern 跨文件）；局部仅本函数/代码块
// 缺点：全局变量破坏封装、多线程并发访问要加锁、难单测，能少用就少用
```
**关联项目**：通用基础、市场问题分析eMMC-eSIM（全局缓冲区 RAM 占用分析）

### const 与 volatile 能同时修饰一个变量吗
**一句话要点**：能。const 表示程序本身不能写它，volatile 表示它的值可能被外部（中断、硬件、多线程）意外改变，两者管的是不同维度、语义不冲突，合起来表示"程序只读但值随时会变"。
**面试怎么问**：const 和 volatile 能同时修饰一个变量吗？什么场景需要 const volatile？只读硬件寄存器为什么要加 volatile？
**用例 / 示例**：
```c
// 场景 1（最典型）：只读硬件状态寄存器——程序不能写，硬件随时改
#define REG_STATUS (*(const volatile uint32_t *)0x40001000)
while (REG_STATUS & 0x01) {
    /* 等待硬件置位：const 禁止程序写，volatile 防止编译器缓存旧值 */
}

// 场景 2：中断里修改、主程序只读的标志
// 注意：ISR 要写它，变量本身不能加 const（const 变量赋值会编译报错）；
// 主程序通过 const volatile 指针访问，保证只读且每次从内存读
volatile int g_irq_flag = 0;                    // 中断要写，只加 volatile
const volatile int *flag_view = &g_irq_flag;   // 主程序视角：只读 + 防缓存

void ISR(void) { g_irq_flag = 1; }             // 中断里写

void main_loop(void)
{
    if (*flag_view) { /* 读到的永远是最新值，不会被编译器缓存 */ }
}

// 记忆：const 管"程序内能不能写"，volatile 管"值会不会被外部改"，
// 两个维度互不冲突，所以能共存
```
**关联项目**：GNSS 固件升级（寄存器/中断标志）、主动安全系统（状态寄存器）

### static 的缺点与使用注意事项
**一句话要点**：static 虽好用但有四个缺点：① 静态变量常驻内存、持有大资源不释放造成浪费/泄漏风险；② 多线程共享静态变量、无同步会竞态；③ 过度使用导致模块耦合、单元测试难 mock；④ 持有状态使函数不可重入、多次调用结果不可控。
**面试怎么问**：static 有什么坏处？为什么嵌入式里 static 大数组要慎用？什么样的函数是不可重入的？
**用例 / 示例**：
```c
// 缺点 1：常驻内存——static 大数组不随函数退出释放
void load_cfg(void)
{
    static uint8_t big[1024 * 1024];   // 常驻全局区，函数返回也不释放
    // 若只是初始化期用一次，应改为 malloc + free 或临时栈/堆
}

// 缺点 2：线程安全——多线程共享 static 变量，无同步会竞态
static int g_count = 0;
void bump(void) { g_count++; }         // 两个线程同时调 -> 丢更新
// 需加锁或原子操作（见"volatile 能保证线程安全吗"小节）

// 缺点 3：耦合与可测试性——static 内部状态难注入、难 mock、难单测
// static int g_state = 0;  // 外部无法构造测试场景，只能靠真实调用积累

// 缺点 4：破坏可重入性——持有状态的函数不可重入
static int g_seq = 0;
int next_id(void)        // 不可重入：中断/多线程并发调用结果不可控
{
    return g_seq++;      // 第 1 次返回 0、第 2 次返回 1……依赖历史调用
}
// 可重入版本：把可变状态放参数里，由调用方持有
int next_id_r(int *seq) { return (*seq)++; }

// 结论：static 适合"只读配置、只初始化一次"的场景；
// 需要"每次调用相互独立"的函数不要用 static 保存可变状态
```
**关联项目**：主动安全系统（多线程共享变量）、通用基础

### 指针运算笔试题（数组与指针自增）
**一句话要点**：*p++ 等价于 *(p++)——先取 *p 的值，再把 p 加 1（后缀 ++ 作用于 p，解引用的是自增前的 p）；int 指针 +1 实际跳 sizeof(int)=4 字节。
**面试怎么问**：int a[5]={1,2,3,4,5}; int *p=&a[1]; p++; int m=*p++; m 是多少？p 指向哪里？*p++ 和 (*p)++ 有什么区别？
**用例 / 示例**：
```c
int a[5] = {1, 2, 3, 4, 5};   // 假设 a 首地址 0x2000106c（32 位）
// 地址布局：a[0]=1 @0x2000106c，a[1]=2 @0x20001070，
//          a[2]=3 @0x20001074，a[3]=4 @0x20001078

int *p = &(a[1]);   // p 指向 a[1]（值 2，地址 0x20001070）
p++;                // p 指向 a[2]（值 3，地址 0x20001074）
int m = *p++;       // 等价于 m = *(p++)：
                    // 先取 *p（当前 p 指向的 a[2] == 3）赋给 m，
                    // 然后 p 自增 1 -> 指向 a[3]（地址 0x20001078）
// 结果：m == 3，p == &a[3]（地址 0x20001078）

// 关键辨析：
// *p++  == *(p++)   先解引用再自增（p 前进 1 个元素）
// (*p)++            先解引用，把 *p 的值加 1（指针不动，元素值 +1）
// *++p              先自增再解引用（p 先前进，再取新位置的 *p）
// ++*p              等价于 ++(*p)：先解引用再给元素加 1
// 地址计算：int 指针 +1 实际跳 4 字节，0x...70 -> 0x...74 -> 0x...78
```
**关联项目**：通用基础（笔试必考）、GNSS 固件升级（指针遍历缓冲）

### C 代码排查题（返回局部数组指针）
**一句话要点**：char *myString() 返回局部数组 buffer 的地址是错误写法——函数返回后栈上数组已释放，返回的是悬垂指针（未定义行为），打印结果不可预期甚至崩溃；改正方法：static 数组（注意不可重入）、malloc（调用方 free）、或由调用方传入缓冲区。
**面试怎么问**：下面这段代码哪里错了？为什么输出不是 "hello"？返回局部数组有哪几种正确写法？
**用例 / 示例**：
```c
// 错误代码：返回局部数组地址
char *myString_bad(void)
{
    char buffer[16] = "hello";   // 局部数组在栈上
    return buffer;               // 函数返回后栈帧销毁，buffer 成悬垂指针！
}
// 调用方：char *s = myString_bad();
// printf("%s", s);   // 未定义行为：可能打印乱码/崩溃（栈被后续调用覆盖）

// 改正方法 1：static 数组（生命周期延长到程序结束，注意不可重入）
char *myString_static(void)
{
    static char buffer[16] = "hello";   // 静态存储期，函数返回仍有效
    return buffer;                      // 缺点：多次调用共享同一块，见 static 缺点小节
}

// 改正方法 2：malloc（调用方负责 free，注意判空）
char *myString_malloc(void)
{
    char *p = malloc(16);
    if (p == NULL) return NULL;
    strcpy(p, "hello");
    return p;               // 调用方：char *s = myString_malloc(); ... free(s);
}

// 改正方法 3：调用方传入缓冲区（最推荐，嵌入式常用）
void myString_out(char *out, size_t len)
{
    if (out == NULL || len < 6) return;   // 边界校验
    strncpy(out, "hello", len - 1);
    out[len - 1] = '\0';
}
// 调用方：char buf[16]; myString_out(buf, sizeof(buf));
// printf("%s\n", buf);    // 输出 "hello"
```
**关联项目**：通用基础（高频手写题）、市场问题分析eMMC-eSIM（悬垂指针崩溃定位）

### 面经补充：Linux 命令与调试

#### mkdir 与 mkdir -p 的区别
**要点**：mkdir 只能创建单层目录，父目录不存在会报错；mkdir -p 递归创建多级目录，目录已存在也不报错，脚本里最常用。面试常问"-p 到底解决了什么"——就是"递归创建 + 已存在不报错"。
```bash
mkdir logs            # 创建单层 logs
mkdir a/b/c           # 失败：a、a/b 不存在
mkdir -p a/b/c        # 递归创建 a -> a/b -> a/b/c，已存在也不报错
mkdir -p /tmp/tbox/{log,cfg}   # 大括号展开，一次建多个目录
```

#### 查看内存使用情况
**要点**：free 看总量/已用/可用（-h 人性化单位）；top 动态刷新、按 M 键按内存排序；ps 按内存降序列进程（--sort=-%mem）；cat /proc/meminfo 看内核视角明细；vmstat 看换页统计。排查内存泄漏时连续观察某个进程的 RSS 是否只涨不降。
```bash
free -h                          # 总/已用/可用内存，-h 以 G/M 显示
top                              # 动态刷新，按 M 键按内存排序
ps aux --sort=-%mem | head       # 按内存占用降序列出前几个进程
cat /proc/meminfo                # MemTotal/MemFree/SwapTotal 等明细
vmstat 1 5                       # 每秒一次共 5 次；si/so 看换页，free 看剩余

# 盯一个进程的内存趋势（泄漏排查常用）
ps -o pid,rss,cmd -p <pid>       # 多执行几次，观察 RSS 是否只涨不降
```

#### 软件开发完之后怎么调试程序
**要点**（完整流程）：编译加 -g -O0 保留调试信息 → 先运行观察现象、确认复现条件 → 日志定位（打印/syslog）→ 崩溃现场抓 core → gdb 看调用栈和变量 → strace 看系统调用行为（打开哪些文件、读写什么）→ valgrind 查内存问题 → 定位修复 → 重新编译回归验证。
```bash
# 1. 编译带调试信息
gcc -g -O0 -Wall -o app main.c
# 2. 运行复现，抓日志
./app > app.log 2>&1
# 3. 崩溃产生 core，用 gdb 分析
ulimit -c unlimited; ./app
gdb ./app core -ex bt -ex quit
# 4. 行为层面：strace 跟踪系统调用
strace -f -o trace.txt ./app
# 5. 内存层面：valgrind 查泄漏/越界
valgrind --leak-check=full ./app
# 6. 修复后重新编译，回归验证原现象消失、无新问题
```

### 面经补充：嵌入式 Linux 系统知识（概念级）

#### U-Boot 的作用与嵌入式启动流程
U-Boot 是引导加载程序（Bootloader），负责硬件初始化和加载内核。上电后芯片固化的 BootROM 先执行（初始化最小硬件，从 eMMC/SD/网络把 U-Boot 加载进 RAM），然后 U-Boot 初始化 DDR、时钟、串口，按 bootcmd 从存储介质读内核镜像和设备树到内存，最后跳转执行内核。对我们做应用层的人来说，这个流程决定了应用什么时候能跑、依赖哪些服务：日志停在 U-Boot 阶段多半是存储介质或引导配置问题，停在内核之后才轮到应用层排查。

#### 设备树 Device Tree
设备树是描述硬件信息的文本数据结构（.dts 编译成 .dtb），内核启动时解析它，知道平台有哪些外设、寄存器地址、中断号等，实现"驱动代码与硬件配置分离"。驱动通过 compatible 属性与设备节点匹配（如 compatible = "ti,am335x-uart"），匹配成功后驱动 probe 被调用，再读 reg/interrupts 等属性拿到资源。好处是同一份内核可跑不同硬件，改板子只改设备树不用改驱动源码。应用层关联：我们 open 的 /dev/ttyS0 就是设备树描述、驱动 probe 时注册出来的节点。

#### 驱动 vs 应用程序
驱动运行在内核态，有完全权限，通过 file_operations 结构体向用户态暴露接口（open/read/write/ioctl/release）；用户程序 open("/dev/xxx") 后，read/write 最终会调用到驱动里对应的函数。应用运行在用户态，受限、崩溃不拖垮系统，通过系统调用与内核交互。应用层面试答法：我们写的是应用，调用 open/read/write/ioctl 时由 VFS 分发到具体驱动的 file_operations，驱动负责硬件访问、中断处理和数据搬运。

#### 用户态 vs 内核态、系统调用流程
CPU 分特权级：用户态（非特权）不能直接访问硬件和内核数据，内核态（特权）可以。应用要操作硬件必须走系统调用：调用库函数（如 read）→ 触发软中断/专用指令（ARM 是 SVC）→ 陷入内核 → 内核按系统调用号执行对应服务 → 需要传数据时用 copy_from_user/copy_to_user 在用户/内核缓冲间安全搬运 → 返回用户态。关联：用户态崩溃只是进程死，内核态崩溃是 panic 整机挂；驱动里的 copy_from_user 就是干这个的。

#### fork 与 pthread_create 区别
fork 创建进程：复制父进程的地址空间，Linux 用写时复制（COW）——创建时不真正拷贝页，谁先写谁复制，父子独立、通过 IPC 通信。pthread_create 创建线程：同一进程内共享地址空间、全局变量、文件描述符，各自只有独立的栈和寄存器，通信靠共享内存加同步。线程创建开销小、切换快，但共享数据要加锁；进程隔离性好、一个崩溃不影响另一个。嵌入式里多任务以线程为主，需要强隔离或独立崩溃恢复才用进程。

#### 僵尸进程 vs 孤儿进程
僵尸进程：子进程先退出，但父进程没调用 wait/waitpid 回收，进程的 PCB 残留在内核，不执行但占资源，ps 显示 Z 状态。孤儿进程：父进程先退出，子进程被 init/systemd（PID 1）收养，由它负责回收。预防办法是父进程及时 wait/waitpid 或注册 SIGCHLD 处理；长期运行的服务出现大量僵尸，说明父进程没回收，要查代码。应用层关联：我们 spawn 子进程（升级脚本、拨号程序等）后必须 wait 回收，否则僵尸累积。

#### 虚拟内存与页表
每个进程都有独立虚拟地址空间，MMU 加页表把虚拟地址翻译成物理地址；进程只能看到自己的虚拟地址，天然隔离。好处：按需分配（申请虚拟页不一定分配物理页，访问时才缺页填充）、共享（同一物理页映射多个进程，如动态库）、保护（页属性只读/不可执行）。应用层关联：malloc 拿到的是虚拟地址；报 OOM 说明物理内存耗尽，而虚拟地址空间耗尽很少见。

#### malloc 与 mmap 区别
malloc 是 C 库函数，参数是字节数，管理用户堆；mmap 是系统调用，可把文件或匿名内存映射到进程地址空间，返回基地址。malloc 底层小内存走 brk、大内存走 mmap（见「C 语言内存分布与管理」页的 malloc 底层原理知识点）。区别要点：malloc 是库接口、有 chunk 管理开销；mmap 是内核接口、页粒度（4K 对齐）、可映射文件（如固件镜像只读映射省内存）、释放时直接 munmap 还给系统。嵌入式大块缓冲、固件镜像、共享内存常用 mmap。

#### select/poll/epoll 区别
三者都是 I/O 多路复用，让一个线程同时监听多个 fd。select 用 fd_set 位图，默认上限 1024，每次调用要全量拷贝 fd 集合、内核线性扫描，O(n)；poll 用 pollfd 数组，去掉 1024 上限，但仍是全量扫描；epoll 是 Linux 专属事件驱动：epoll_ctl 注册关心的 fd，内核只通知就绪的 fd，用红黑树加就绪链表，复杂度 O(就绪数)，大量连接时性能碾压前两者。应用层关联：T-Box 要同时管网络 socket、串口、信号时，高并发服务用 epoll，简单场景 select 够用。

#### 中断上下半部
中断处理要快，所以分成两部分：上半部（Top Half）就是 ISR，关中断或快速执行，只做最必要的（读寄存器、清中断标志、标记待处理），不能睡眠、不能做耗时操作；下半部（Bottom Half，软中断/tasklet/工作队列）延后执行耗时处理，可被调度。应用层关联：驱动中断里只置标志、唤醒等待的任务或往环形缓冲写数据，真正的解析和上报在进程上下文做；"中断里不能 sleep"就是因为中断上下文不可调度。

#### mutex/semaphore/spinlock 区别
mutex 互斥锁：同一时刻只有一个线程持有，持有者可以睡眠，适合长时间持锁；semaphore 信号量：带计数，可做资源管理（n 个资源允许 n 个访问者），计数为 0 时阻塞；spinlock 自旋锁：获取不到就忙等（原地转圈），不睡眠，适合临界区极短且持锁期间不能睡眠的场景（如中断上下文）。选择原则：临界区长用 mutex，微秒级短临界区用 spinlock，多资源并发用 semaphore。RTOS 里的 taskENTER_CRITICAL 类似 spinlock。

#### 死锁与优先级反转
死锁：两个以上线程互相等待对方持有的锁，谁也前进不了。产生需同时满足四个必要条件——互斥、持有并等待、不可抢占、循环等待，破坏任意一条即可预防（按固定顺序加锁、trylock 超时等）。优先级反转：低优先级任务持锁，高优先级任务等锁，中优先级任务又抢占低优先级任务，导致最高优先级被"反转"拖慢。解决：优先级继承（低优先级任务持锁期间临时提升到等锁任务的最高优先级）或优先级天花板。RTOS 的互斥量通常自带优先级继承，信号量没有。

#### 文件描述符与"一切皆文件"
Linux 把普通文件、目录、设备、socket、管道统一抽象成"文件"，用户态都通过文件描述符（fd，一个整数）操作：open 返回 fd，read/write/close/ioctl 都拿 fd 干活，VFS 层把操作分发到具体文件系统或设备驱动。好处是接口统一，写应用不用区分操作对象是 U 盘还是串口。应用层关联：串口就是 /dev/ttyS0 的文件，CAN 用 SocketCAN（也是 socket 文件），/proc、/sys 也是文件视图；fd 是有限资源（ulimit -n），用完必须 close。

#### 缺页异常 Page Fault
页表里没有对应物理页或权限不匹配时，CPU 触发缺页异常，由内核处理——但不一定出错：按需分配（malloc 后第一次访问才真正分配物理页）、写时复制（fork 后写共享页）都是正常流程，内核静默补齐；只有非法访问（地址未映射、越权写只读页）才向进程发 SIGSEGV 崩溃。应用层关联：malloc 大块内存成功不报错，真正写第一遍时可能 OOM；我们遇到的段错误多是野指针/越界访问了没映射的虚拟地址。

#### Linux 启动流程
完整链路：BootROM（芯片固化）→ U-Boot（初始化 DDR/外设，加载内核和设备树）→ 内核解压自解压、初始化（setup_arch、驱动注册、挂载根文件系统）→ 执行根文件系统里的 /sbin/init（或 systemd）→ systemd 按依赖顺序启动服务（udev、网络、业务进程）→ 应用起来后开机完成。应用层关联：开机慢或起不来按阶段定位——串口日志停在 U-Boot 是引导问题，停在 "VFS: Cannot open root device" 是根文件系统或内核参数问题，服务起不来是 systemd 依赖或应用自身问题。

### 面经编程题（手写，完整 C 代码，含边界处理与复杂度）

#### 将数组所有 0 移到末尾（双指针，不允许新开数组）
**思路**：快慢指针——slow 指向下一个非零元素该放的位置，fast 遍历；遇到非零就和 slow 处交换，slow 前进。一次遍历完成，时间 O(n)、空间 O(1)。边界：空数组、全 0、全非零都自然正确。
```c
void move_zeroes(int *a, int n)
{
    int slow = 0;
    for (int fast = 0; fast < n; fast++) {
        if (a[fast] != 0) {
            if (fast != slow) {            // 非零元素前移（交换）
                int t = a[slow];
                a[slow] = a[fast];
                a[fast] = t;
            }
            slow++;
        }
    }
}
// 例：[0,1,0,3,12] -> [1,3,12,0,0]
// 时间复杂度 O(n)，空间 O(1)
```

#### 矩阵旋转 90 度（n×n 原地旋转）
**思路**：两步合成顺时针 90 度——先沿主对角线转置（a[i][j] 与 a[j][i] 交换），再逐行左右翻转；逆时针则是转置加上下翻转。原地 O(1) 额外空间，时间 O(n²)。边界：n 为 1 时两步都不产生交换，天然正确。
```c
void rotate90(int n, int a[n][n])
{
    // 1. 沿主对角线转置
    for (int i = 0; i < n; i++)
        for (int j = i + 1; j < n; j++) {
            int t = a[i][j];
            a[i][j] = a[j][i];
            a[j][i] = t;
        }
    // 2. 每行左右翻转
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n / 2; j++) {
            int t = a[i][j];
            a[i][j] = a[i][n - 1 - j];
            a[i][n - 1 - j] = t;
        }
}
// 例：n=3，1 2 3 / 4 5 6 / 7 8 9  ->  7 4 1 / 8 5 2 / 9 6 3
// 时间复杂度 O(n^2)，空间 O(1)
```

#### 字符串编辑距离（动态规划）
**思路**：dp[i][j] 表示 word1 前 i 个字符变成 word2 前 j 个字符的最小操作数。字符相等继承 dp[i-1][j-1]；不等则取"增、删、改"三种操作的最小值加 1。初始化 dp[i][0]=i（全删）、dp[0][j]=j（全插）。时间 O(m*n)，空间 O(m*n)（可优化为两行滚动数组）。
```c
#include <string.h>

int edit_distance(const char *a, const char *b)
{
    int m = (int)strlen(a), n = (int)strlen(b);
    int dp[m + 1][n + 1];

    for (int i = 0; i <= m; i++) dp[i][0] = i;   // a 的前 i 个全删
    for (int j = 0; j <= n; j++) dp[0][j] = j;   // 全插入成 b 的前 j 个

    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (a[i - 1] == b[j - 1]) {
                dp[i][j] = dp[i - 1][j - 1];      // 末字符相同，不操作
            } else {
                int t = dp[i - 1][j] < dp[i][j - 1]
                        ? dp[i - 1][j] : dp[i][j - 1];   // 删 / 增
                t = t < dp[i - 1][j - 1] ? t : dp[i - 1][j - 1]; // 改
                dp[i][j] = t + 1;
            }
        }
    }
    return dp[m][n];
}
// 例：edit_distance("kitten", "sitting") == 3
// 时间复杂度 O(m*n)，空间 O(m*n)
```

#### 贪心算法：任务调度 / 最小化总完成时间
**思路**：多台机器（CPU 核）安排一批任务使总完成时间（makespan）最短，经典贪心是 List Scheduling——每次把任务分给当前负载最小的机器。实现简单（O(n·k)），但不保证全局最优：如任务 {3,3,2,2,2,2,2}、2 台机器，贪心得 9，最优是 8（两边各 {3,3,2} 和 {2,2,2,2}）。面试要主动说"贪心是近似解，最优是 NP 难问题"，再补一句"按任务时长从大到小排序（LPT）能改善近似比"。
```c
// 简单示例：k 台机器，把 jobs[] 依次分给最空闲的机器
int min_makespan(int jobs[], int n, int k)
{
    int load[16] = {0};              // 每台机器当前负载（k <= 16 演示）
    for (int i = 0; i < n; i++) {
        int min_idx = 0;
        for (int j = 1; j < k; j++) {
            if (load[j] < load[min_idx]) min_idx = j;   // 最空闲的机器
        }
        load[min_idx] += jobs[i];    // 分配任务
    }
    int max = load[0];
    for (int j = 1; j < k; j++) {
        if (load[j] > max) max = load[j];
    }
    return max;                      // 总完成时间
}
// 例：jobs={3,2,2,1}，k=2 -> 机器1:{3,1}=4，机器2:{2,2}=4，makespan=4
// 反例：jobs={3,3,2,2,2,2,2}，k=2 -> 贪心 9，最优 8（贪心是近似解）
```

#### 01 背包问题（动态规划）
**思路**：n 个物品，每个只能选一次（0/1），重量 w[i]、价值 v[i]，背包容量 cap，求最大价值。dp[j] 表示容量 j 能装的最大价值，转移 dp[j] = max(dp[j], dp[j-w[i]] + v[i])。一维数组必须**倒序**遍历容量，保证每个物品最多取一次（正序会退化成完全背包）。时间 O(n*cap)，空间 O(cap)。
```c
int knapsack01(int w[], int v[], int n, int cap)
{
    int dp[cap + 1];
    for (int j = 0; j <= cap; j++) dp[j] = 0;   // 容量 0..cap，初始 0

    for (int i = 0; i < n; i++) {                 // 遍历每个物品
        for (int j = cap; j >= w[i]; j--) {       // 倒序！防一个物品取多次
            int cand = dp[j - w[i]] + v[i];
            if (cand > dp[j]) dp[j] = cand;       // 取或不取
        }
    }
    return dp[cap];
}
// 例：w={2,3,4}, v={3,4,5}, cap=5
// 选物品 1+2（重 5 价 7）最优，返回 7
// 为什么倒序：倒序时 dp[j-w[i]] 还是上一轮的旧值（未装过本物品），
// 正序时它可能已被本轮更新（等于已装入），就变成完全背包了
// 时间复杂度 O(n*cap)，空间 O(cap)
```

#### TCP 数据格式怎么定义
**要点**：TCP 报文头最少 20 字节：源端口/目的端口各 16bit、32bit 序号、32bit 确认号、4bit 首部长度、6bit 保留、6bit 标志位（SYN/ACK/FIN/RST/PSH/URG）、16bit 窗口大小、16bit 校验和、16bit 紧急指针；与 UDP 头对比：UDP 头固定 8 字节，无序号/确认/标志/窗口等可靠性字段。
```text
TCP 报文头字段示意（最少 20 字节）：
+-------------------------------+-------------------------------+
| 源端口 (16 bit)               | 目的端口 (16 bit)             |
+-------------------------------+-------------------------------+
| 序号 Sequence Number (32 bit)                                |
+---------------------------------------------------------------+
| 确认号 Acknowledgment Number (32 bit)                         |
+---------------------------------------------------------------+
| 首部长度(4) | 保留(6) | 标志位(6) | 窗口大小 Window (16 bit)   |
+-------------------------------+-------------------------------+
| 校验和 Checksum (16 bit)      | 紧急指针 Urgent Pointer (16)  |
+-------------------------------+-------------------------------+
标志位：SYN 建立连接 / ACK 确认 / FIN 关闭连接 / RST 重置 /
        PSH 立即交付 / URG 紧急数据
与 UDP 头对比：UDP 头固定 8 字节 = 源端口 16bit + 目的端口 16bit +
        长度 16bit + 校验和 16bit；没有序号/确认/标志/窗口字段，
        无可靠性保证，适合音视频等实时场景
```

#### TCP 三次握手（可背版本）
**要点**：客户端发 SYN（带初始序号 seq=x）→ 服务端回 SYN+ACK（确认 x+1，并带自己的序号 seq=y）→ 客户端回 ACK（确认 y+1），连接建立。为什么三次而不是两次：两次握手服务端无法确认"客户端能否收到自己的报文"（客户端收不到 SYN+ACK 也不会知道），且服务端可能在客户端未确认时就建立半开连接、浪费资源；第三次 ACK 同时确认了"客户端可达服务端"，还能让服务端区分"新连接请求"与"网络中滞留的旧 SYN"，防止误建连接。
```text
Client                         Server
  |  SYN(seq=x)                  |
  |----------------------------->|  1. 客户端发起连接，带初始序号 x
  |  SYN+ACK(seq=y, ack=x+1)     |
  |<-----------------------------|  2. 服务端确认收到 x，并带自己的序号 y
  |  ACK(ack=y+1)                |
  |----------------------------->|  3. 客户端确认收到 y，连接建立
（与网站"网络与 MQTT"页面呼应，面试口头可背：SYN -> SYN+ACK -> ACK）
```

#### Git 常用命令
**要点**：merge 合并保留双方历史、产生合并提交节点；rebase 把当前分支的提交"变基重放"到目标分支顶端、历史线性（不要对已推送的分支 rebase）；reset 移动 HEAD 回退、可能丢提交（仅本地），revert 用新提交反向撤销、保留历史（适合已推送分支）；日常流程 add -> commit -> pull -> push。
```bash
# 克隆远程仓库
git clone git@github.com:user/repo.git

# 工作区 -> 暂存区 -> 本地仓库
git add file.c                # 把改动加入暂存区
git commit -m "fix: 修复串口超时"     # 提交到本地仓库

# 与远程同步
git push origin main          # 推送到远程
git pull origin main          # 拉取远程并合并（等价 fetch + merge）

# 分支操作
git branch feature/ota        # 新建分支
git checkout feature/ota      # 切换分支（新版也可用 git switch）
git merge feature/ota         # 把特性分支合并进当前分支（保留历史，产生合并节点）
# merge vs rebase 的区别：
git rebase main               # 把当前分支提交重放到 main 顶端，历史线性
                              # merge 像"汇合"，rebase 像"重演"

# 查看与对比
git log --oneline             # 一行一条提交记录
git status                    # 查看工作区/暂存区状态
git diff                      # 查看未暂存的改动
git diff --cached             # 查看已暂存的改动

# 回退
git reset --hard HEAD~1       # 丢弃最近 1 次提交（本地回退，慎用）
git revert HEAD               # 用新提交反向撤销（保留历史，适合已推送分支）
```

**从零推送到 GitHub 的标准流程**：
```bash
git init                                  # 1. 初始化本地仓库
git add .                                 # 2. 把所有文件加入暂存区
git commit -m "first commit"              # 3. 首次提交
git branch -M main                        # 4. 主分支命名为 main
git remote add origin git@github.com:user/repo.git   # 5. 关联远程仓库
git push -u origin main                   # 6. 首次推送并建立跟踪关系
# 之后日常开发：git add -> git commit -> git pull（先拉后推避免冲突）
#             -> git push
```
