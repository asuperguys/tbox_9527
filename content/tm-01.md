## 一、项目背景(开场讲述用)

**产品**:TM8765Pro 车载智能一体机(郑州天迈科技)
**本代码库角色**:AI 子系统进程(`AI` 可执行程序),运行在 **联咏 Novatek NT98336** 平台(aarch64 架构,ARM Cortex-A53),是车载机的"智能分析大脑"。

车载机通常有多个子系统(AV 视频、SCH 调度、UI 界面、AI 智能、NET 网络),通过**域间通信(Unix域Socket)**协作。AI 子系统专注:**视频智能分析(主动安全算法)+ 报警业务 + 平台对接**。

**核心业务:主动安全(ADAS/DMS/BSD 等驾驶辅助报警)**

- 通过车载摄像头实时采集驾驶画面
- 调用 AI 算法(虹软 ArcSoft,可切换魔视 Motovis)分析
- 检测到危险行为(疲劳驾驶、打电话、抽烟、车道偏离、前车碰撞、盲区危险等)立即报警
- 联动:语音提醒(TTS)、抓拍/录像附件上传、平台报警上报
- 配套:参数管理(平台/App下发)、外设数据接入(仪表CAN、六轴传感器、倒车/盲区雷达)、三急报警

## 三、主动安全模块架构(mdlSafety)— 分层设计

这是面试讲述的核心:10个子模块,按"**职责分离 + 依赖单向**"设计,类似"洋葱模型":

```
┌─────────────────────────────────────────────────────┐
│  业务逻辑层(safety_main 主控 / alarm_process 报警)   │
├─────────────────────────────────────────────────────┤
│  能力层(协议:ti/subiao · 参数:safety_conf ·         │
│          外部数据:external_data_center · 激活:      │
│          alg_activate)                               │
├─────────────────────────────────────────────────────┤
│  算法抽象层(alg_abstract_api_st:统一API)            │
│      ├── 虹软实现 alg_api_ARC.cpp                   │
│      └── 魔视实现 alg_api_MOTOVIS.cpp               │
├─────────────────────────────────────────────────────┤
│  适配层(adapter:共享内存/域通信/日志/工具)          │
└─────────────────────────────────────────────────────┘
```

**分层设计原则(面试要点)**:

1. **算法厂商无关**:业务层只依赖 `alg_abstract_api.h` 统一接口,换算法厂商(虹软↔魔视)只需改抽象层内部实现,业务零改动。
2. **平台协议隔离**:报警业务不直接组协议包,而是调协议模块接口;协议模块内部按编译宏区分天迈/苏标。
3. **设备适配隔离**:所有外部依赖(摄像头数据、与SCH/AV通信、日志、时间)都经 adapter 封装,移植到新设备只改适配层。
4. **单向依赖**:业务层 → 能力层 → 抽象层 → 适配层,不允许反向调用。

## 四、核心数据流(必背)

### 链路1:算法报警全流程(面试必讲)

```
AV子系统 ──共享内存写YUV帧──▶ AI侧 Task_BlockedFeedData(每算法一个线程)
    │
    │ 1. 从共享内存取一帧YUV420(NV21)
    │ 2. 更新车辆状态(速度/转向/刹车)
    │ 3. 调用统一检测接口 ALG_xxx_Detect()
    ▼
算法计算结果(DmsResult_t / AdasResult_t / BsdResult_t)
    │
    │ 4. ALG_eventVec() 按位掩码转为通用报警事件
    │ 5. Alarm_SafetyEvent(module, event, result)
    ▼
alarm_process(报警处理中心)
    │ 6. 冷却过滤(ALG_InCoolDown)
    │ 7. 生成报警序号sn
    │ 8. 组附件请求 → 发AV子系统生成抓拍/录像(0x0102)
    │ 9. 按协议上传平台(天迈0x0201 / 苏标)
    ▼
ti_safety_protocol / subiao_safety_protocol → 平台服务器
```

### 链路2:参数下发(平台→设备)

```
平台下发 0x8504(设置终端参数)
    ▼
ti_protocol_manager 解析命令字
    ▼
safety_para_manager.SetPara(event, data) → 写SQLite(三张表)
    ▼
内存参数更新 + 通知回调(TableUpdNotifySafetyPara)
    ▼
(报警参数变化时) → SafetyConf_LoadDmsParaToAlg() → 算法重初始化
```

### 链路3:外部数据接入(SCH→AI)

```
调度子系统(SCH)通过域通信发送:
  SCH_DASHBOARD_EVENT(仪表CAN) ──▶ SafetyFunc_DashboardData ──▶ external_data_center 解析
  SCH_SIX_AXIS_EVENT(六轴传感器) ──▶ (当前代码注释) ──▶ 三急算法
  SCH_BSD_RADAR_EVENT(盲区雷达) ──▶ (当前代码注释)
  SCH_CAN_DATA(倒车雷达) ──▶ (当前代码注释)
```

> ⚠️ 面试注意:unixprotocol.cpp 中倒车/六轴/盲区雷达入口当前是注释状态,但 external_data_center 的解析逻辑是完整的。你的角色在这里——可讲"解析逻辑已实现,域通信接入点按需开放"。

## 五、线程模型(嵌入式方向面试重点)

### AI进程启动的线程(main.cpp ThreadStart)

| 线程名 | 职责 |
|---|---|
| kldebugserver | 客流调试TCP服务 |
| tcpserver | TCP服务(旧) |
| unixclient | 域通信客户端(收各子系统数据) |
| dataprocess | 域通信数据处理 |
| pccount | 客流计数 |

### 主动安全模块线程(safety_main)

| 线程 | 职责 |
|---|---|
| **DealProtocol** | 天迈协议收包处理(阻塞select循环) |
| **SafetySecTask** | 协议秒级定时任务(注册/鉴权/心跳/定位/补传写盘) |
| **TmAdxUpload** | 天迈附件上传(HTTP) |
| **SafetyIniData** | 内存文件(ini)定时更新(UI查询用) |
| **alg_DMS / alg_ADAS / alg_BSD1 / alg_BSD2** | ⭐每路算法一个喂数据线程(Task_BlockedFeedData) |
| **Task_BlockedActivateSdk** | 算法激活线程(循环激活直到成功) |
| **重传线程** | ReSend808Controller内部线程 |

### 算法线程设计要点(面试亮点)

`Task_BlockedFeedData`(safety_task_run.cpp):
- 每个启用模块一个线程(由 `moduleEnable` 配置决定)
- 启动流程:**等待激活 → 等待算法初始化 → 共享内存初始化 → 循环取帧计算**
- 取帧同步:**共享内存 + 计数器 + 文件锁** 机制
  - AV侧写YUV到 `/tmp/shareMemChn_N`,更新计数器
  - AI侧:加锁 → 检查计数器是否变化 → 变化则拷贝 → 解锁
  - 计数器未变(还是上一帧)→ 解锁+usleep出让CPU
- **性能控制**:速度无效(≤0)时不计算;`speedLimit` 字段做速度上下限控制(TODO未完全生效)
- **帧率统计**:统计周期内平均帧率 + 单帧算法耗时,用于判断芯片性能是否够用
- **锁保护**:计算期间加锁,防止参数修改/去初始化导致崩溃

## 六、构建系统与编译开关(嵌入式方向加分点)

Makefile 关键宏(面试常问):

```makefile
# 主动安全总开关
ACTIVITY_SAFTY=y            → -DACTIVITY_SAFTY
# 协议选择:1天迈 2苏标
SAFETY_PROTOCOL=1           → -DSAFETY_PTO_TIAMAES / -DSAFETY_PTO_808JSU
# 泰国特殊需求(不播TTS)
SUPPORT_THAILAND=n
# 算法厂商:arc虹软 / motovis魔视
SAFETY_ALGORITHM=arc        → -DSAFETY_ALGORITHM_ARC
```

- 虹软:链接 `-larcnpu -lArcSoftVisDrive_NT9833x -lArcSoftVisDriveDMS -lArcSoftVisDriveFR -lArcSoftVisDriveADAS -lArcSoftVisDriveBSD`
- 魔视:链接静态库 + opencv 依赖
- 平台:TM8765Pro → `aarch64-ca53-linux-gnu-` 交叉编译链,NT98336平台

**面试可讲的点**:通过编译宏做"功能裁剪 + 多方案并存"(协议/算法/项目变体),一个代码库支撑多产品形态。

## 九、追问提示(本页会被问到的)

- "为什么分这么多层?" → 算法厂商解耦(虹软↔魔视零业务改动)、协议隔离(天迈↔苏标)、设备可移植
- "线程怎么管理?" → ThreadManage统一创建,算法每路一线程,协议收包/定时分离
- "共享内存怎么同步?" → 文件锁 + 计数器,AV写AI读
- "怎么控制算法性能?" → 速度门槛、speedLimit、帧率统计反馈
- "旧的src/Safety是怎么回事?" → 旧版直连平台实现,新架构mdlSafety替代后已被#if 0屏蔽,体现了架构演进
