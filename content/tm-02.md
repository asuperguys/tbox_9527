## 一、模块职责总览

**external_data_center** 负责接入"非视觉类"的外部传感器数据,并把它们变成主动安全报警:

| 数据源 | 来源 | 解析后用途 |
|---|---|---|
| **仪表 CAN 数据** | 调度(SCH)域通信转发 | 车速、挡位、刹车、转向灯 → 供算法/三急/倒车判定 |
| **六轴传感器数据**(ICM-20600) | SCH 域通信转发 | 加速度+陀螺仪 → **三急判定**(急加速/急减速/急转弯) |
| **倒车雷达数据**(CAN) | SCH 域通信转发 | 倒车时4探头距离 → 倒车碰撞/超速报警 |
| **盲区雷达数据**(BSD雷达) | SCH 域通信转发 | 左右盲区障碍物 → 盲区报警 |

**模块文件**:
- `external_data_process.cpp/h` — 四类数据解析入口 + 仪表数据共享
- `external_data_struct.h` — 数据结构定义
- `three_urgent_process.cpp/h` — 三急(急加速/急减速/急转弯)判定算法

## 三、仪表 CAN 数据解析(面试主战场核心)

### 代码位置
`ExternalDataProcess::DashboardDataParse(char *data, int packetLen)` (external_data_process.cpp:248)

### 协议格式(仪表CAN报文封装)

```
MeterCanDataPacket:
┌───────┬────────┬────────┬──────────────────────┬───────┐
│ cmd   │ len    │ total  │ data[1024]           │ crc   │
│ 1字节 │ 2字节  │ 2字节  │ 数据项流             │ 2字节 │
└───────┴────────┴────────┴──────────────────────┴───────┘

MeterCanDataItem(数据项):
┌────────┬────────┬──────────────┐
│ id     │ len    │ data[0]      │
│ 2字节  │ 1字节  │ len字节数据   │
└────────┴────────┴──────────────┘
```

### 解析流程(逐行理解)

```cpp
int ExternalDataProcess::DashboardDataParse(char *data, int packetLen)
{
    // 1. 合法性校验:包长>7字节、total≠0
    // 2. 取出total(数据项总个数)
    // 3. while循环遍历数据项:
    //    item = (MeterCanDataItem*)(packet->data + cursor);
    //    switch(item->id) 按ID解析:
    //      DASHBOARD_SPEED(13001): 车速 = *(short*)item->data
    //      DASHBOARD_BRAKE(21010): brake = (2==item->data[0]) ? 1 : 0
    //      DASHBOARD_REVERSE(21026): 倒车挡
    //      DASHBOARD_LEFT_ID/RIGHT_ID(21001/21002): 转向灯
    //    cursor += 3 + item->len;  // 跳到下一个数据项
    // 4. setDashboardDataFunc(dashboardData) 存入成员(加互斥锁)
}
```

### 关键设计点(面试问答素材)

1. **数据项流式解析**:数据项是变长的(`3 + item->len` 前进),用 total 控制循环次数,边界判断 `(packetLen - 7) > cursor` 防越界。
2. **线程安全**:`std::mutex dashboardDataMutex` 保护仪表数据共享(生产者=解析线程,消费者=算法线程/倒车判定)。
3. **车速来源优先级**(adapterApi_baseStatusData.cpp:30 `devData_getSpeed()`):
   - 测试后门:`/tmp/static_test_alarm` 存在时模拟 30~40km/h(便于现场测试)
   - 仪表CAN车速(优先,更准)
   - 回退:定位(GPS)速度 `position.velocity / 10`
4. **转向灯信号**(adapterApi_baseStatusData.cpp:58 `devData_getTurnSignal()`):仪表左右转 → 回退 IO 左右转(考虑单边未更新情况)。

## 四、倒车雷达解析与报警判定(面试主战场核心)

### 代码位置
- 解析:`ExternalDataProcess::ReverseRadarDataParse` (external_data_process.cpp:220)
- 判定:`ReverseRadarDataProcess(char reverseFlag, char reverseMinDistance)` (external_data_process.cpp:101,全局函数)

### 数据格式(8字节CAN帧)

```
byte0 bit0: 倒车状态(1倒车中 0非倒车)
byte4~7: 4个探头距离(排序后取最小值作为 s32LimitDistance)
```

### 判定逻辑(理解"倒车碰撞/倒车超速"两级报警)

```cpp
ReverseRadarDataProcess(reverseFlag, minDistance):
  1. 从仪表数据取车速 speed(倒车时速度用仪表速度)
  2. 从设备参数取:碰撞时间阈值 alarmTTC(reverseTTC)、倒车限速值 s32AlarmSpeed
  3. 判定"倒车超速": speed >= 限速值 && 未报过超速 → 报超速
  4. 判定"倒车碰撞":
     currTTC = (距离×72)/(速度×100)   // 计算碰撞时间
     距离==0 或 currTTC <= alarmTTC && 未报过碰撞 → 报碰撞
  5. 报警处理:
     - 通知UI显示(AV_RADAR_ALARM 域通信)
     - 组 ReverseRadarEventInfo_t(0x69 子事件) → 平台上传(当前注释)
  6. 倒车结束(flag==0)时复位报警标志(一次倒车只报一次)
```

### 面试讲解要点

- **防重复报警**:`static char alarmflag1/alarmflag2` 标志,一次倒车过程同类型只报一次,倒车结束复位。
- **碰撞时间TTC计算**:`TTC = 距离×72/(速度×100)`,单位0.1s,与平台配置的阈值比较。
- **数据流向**:UI显示(AI→UI域通信)+ 平台上传(0x69子事件,当前注释)。
- **测试价值**:该函数逻辑完整,注释了平台上传,说明当时处于"UI联调阶段"。

## 五、盲区雷达解析(BSD雷达)

### 代码位置
`ExternalDataProcess::BlindRadarDataParse` (external_data_process.cpp:61)

### 解析流程

```cpp
1. 校验:len==8
2. 大小端转换: tool_ReverseEndianSequenceCopy (雷达数据是小端,CAN是大端)
3. 取frame_id: 0x31前右 / 0x32后右 / 0x35后左 / 0x36前左
4. 位解析:
   device_id     = byte2 & 0x1F
   type          = (byte2 >> 5) & 0x07
   warning_mode  = (byte3 >> 4) & 0x0F
   warning_level = byte3 & 0x0F
   warning_zone  = byte4
5. type==0(警告)时调用 BlindRadarDataProcess 生成BSD报警事件(当前仅框架)
```

> 面试可讲:**字节序处理**(雷达小端 vs 系统大端)、**位域解析**(按位提取字段)、**帧ID区分探头位置**。

## 六、六轴传感器与三急算法(面试最核心亮点!)

### 数据流

```
六轴原始数据(short) ──▶ SixAxisSensorDataParse (external_data_process.cpp:308)
   │  lineData[i] = value × 4.0f  (单位:4mg→mg)
   │  gyrosData[i] = value × 4.0f
   ▼
getDirForInstallingEquipment()  ← 根据设备安装方向确定取哪一轴
   ▼
rapidTurnEventDataProcess(gyrosData)  ← 急转弯判定(陀螺仪Z轴)
sharpSpeedEventDataProcess(lineData)  ← 急加速/急减速判定(线性加速度,当前注释)
```

### 6.1 急转弯判定(rapidTurnEvent,three_urgent_process.cpp:72)

```cpp
int ThreeUrgentProcess::rapidTurnEvent(float values[3]):
  1. index = mGyroIndex/2  // 根据安装方向选择的陀螺仪轴
  2. 抖动过滤: |values[index] - 均值| <= sensorJog(0.3) → 用均值代替(抗抖动)
  3. dealGyroDataAvg: 滑动均值(取最近10个值,LST_STEP=10≈2秒数据)
  4. 阈值判定:
     |角速度| >= 角度阈值(trigger_other×0.1度/s)  且
     车速 >= 触发速度(trigger_speed)               且 车速!=0
  5. 方向判定: 正值=左急转弯,负值=右急转弯
  6. 时间间隔过滤: 与上次触发时间差 > 配置的interval(上传间隔)才报警
  7. dealWarnEvent: 按车速分级,执行分级动作
```

**面试核心亮点——陀螺仪温漂处理**:
- 陀螺仪有**温漂/零点漂移**问题,长时间运行数值会偏
- 方案:**滑动窗口均值** + **抖动阈值过滤**(低于阈值视为静止/抖动,用均值替代)
- 代码注释明确说明:传感器数据受车辆晃动、温度影响,需要经验阈值过滤

### 6.2 急加速/急减速判定(RapidAccEventProcess,three_urgent_process.cpp:129)

```cpp
int ThreeUrgentProcess::RapidAccEventProcess(float values[3]):
  1. index = getAccAxisIndex()  // 根据设备安装方向选X或Y轴
  2. balanceAcc = getPredictValue(values)  // 预测平衡值(重力分量消除)
  3. 波形判定:
     values[index] - balanceAcc > 0 → 倒U形 → 急加速
     否则 → U形 → 急减速
  4. dealSharpSpeedChanged:
     抖动过滤: |diff| <= sensorJog(0.3) → 忽略
     加速度阈值: |diff| >= detectTHD(0.7)
     时间间隔过滤
```

**面试核心亮点——平衡值预测算法(getPredictValue)**:

```cpp
原理:加速度计测的是"重力+运动加速度"的合成。
静止时:读数为重力分量(平衡值)。
运动时:读数在平衡值上下波动。
急加速 → 正向波峰(倒U);急减速 → 反向波谷(U形)。

实现:
- mPredictLinearAcc: 预测平衡值,初始0xFF(无效)
- 滑动差值均值 mPreAvgDiff: 最近ACC_STEP=5个差值的均值
- 预测: mPredictLinearAcc = mPreLinearAcc + mPreAvgDiff
- 稳定判定: 速度快速变化后连续3次差值<0.3 → 认为恢复平稳,重新采样平衡值
```

> 这里有个代码注意点:`getPredictValue` 中有一处 `gryoLst.front()` 与 `gryoLst.pop_front()` 疑似笔误(应为 mLinearAccDiff),面试时如被问到可指出"这里滚动窗口写混了,但整体预测逻辑成立"——展示你真读过代码。

### 6.3 分级动作处理(dealWarnEvent,three_urgent_process.cpp:383)

```cpp
void ThreeUrgentProcess::dealWarnEvent(int speed, AlarmType_e eventId, AlarmEventPara_t &eventParaAttr):
  1. 事件开关检查: alarmEvent_switch==0 → 不处理
  2. 按车速分级:
     speed < level_1        → 1级动作(level_1_action)
     level_1 <= speed < level_2 → 2级动作
     speed >= level_2       → 3级动作
  3. 动作位定义(12位,与协议联动字段一致):
     bit0语音提醒 bit1上传图片 bit2上传视频 bit3声光报警
     bit4自带显示器1 bit7外接显示器1 bit9电子后视镜 bit10 360环视 bit11抬头显示
```

```cpp
GetDirForInstallingEquipment() (three_urgent_process.cpp:223):
  - 从数据库读取设备安装方向(devTopDir 机顶壳朝向 / devLedDir LED面朝向)
```

## 七、三急报警链路(从数据到上报的完整旅程)

```
六轴传感器原始数据
  → SixAxisSensorDataParse(单位换算4mg→mg)
  → getDirForInstallingEquipment(选轴)
  → rapidTurnEventDataProcess / sharpSpeedEventDataProcess
  → 抖动过滤 + 均值/预测平衡值 + 阈值判定 + 时间间隔过滤
  → dealWarnEvent(开关检查 + 车速分级)
```

> 最终急转弯、急加速、急减速都能在实车上稳定触发,并且支持平台配置的触发速度/阈值/上传间隔,按车速分级执行不同联动动作。"

## 十、CAN 信号级重构(实战优化:可迁移到整车 1700帧/s 场景)

> **2026-08 重构**:把 external_data_center 从"帧级解析打印"升级为"信号级处理"。
> 这套方法论直接可迁移到你宇通整车 CAN(每秒约1700帧)场景——**面试必讲的高价值亮点**。

### 10.1 重构动机(为什么改)

原实现的问题(高频场景会放大):
1. **整体覆盖**:`DashboardDataParse` 每次收包都新建 `DashboardData_t` 并整体覆盖,未在本帧出现的字段被**误清为默认值**。高频下不同 ID 的帧交错到达,字段互相清空。
2. **无超时处理**:车速/刹车等状态型数据一旦停止更新,业务(算法/三急/倒车判定)仍拿旧值,误以为有效。
3. **业务在收包路径上同步执行**:三急判定直接在数据接收线程里跑,高频下阻塞收包。
4. **高频日志**:六轴数据每帧 LogInfo,日志风暴拖垮系统。
5. **无变化检测**:消费端无法判断"是否有新数据",高频下重复计算。

### 10.2 重构方案(信号级处理,AUTOSAR COM 信号思想)

```
┌──────────────┐   解析线程(收包)   ┌────────────────┐   业务线程(消费)
│ CAN报文/数据项 │ ──拆解为独立信号──▶ │ CanSignalMgr   │ ──按需读取──▶ 算法/三急/倒车
└──────────────┘                   │ 信号注册表+信号槽 │   带有效性判断
                                   │ 超时监控+版本号  │
                                   └────────────────┘
```

### 10.4 面试话术(怎么讲这次重构)

> "我把我负责的外部数据模块做了一个重构,从'帧级解析'升级成'信号级处理'——这也是 AUTOSAR COM 的经典思路,直接迁移到了我后来做整车 CAN(1700帧/秒)的项目。
>
> 核心是三步:一是**信号注册表+信号槽**,把每帧报文拆成独立信号,解析只更新对应信号槽,不再整体覆盖——解决了高频下字段互相清空的问题;二是**超时监控**,状态型信号(车速/刹车/六轴)500ms 没更新就自动失效,业务读取时能感知到数据不可用,避免拿旧值做判定;三是**降频和批量**,三急判定从每帧执行改成 100ms 节流,六轴更新用批量接口一次锁处理 6 个信号,高频日志降到 5 秒一条。
>
> 这套框架是零依赖的,可以整体搬到宇通的整车 CAN 场景,只要把信号注册表换成整车报文矩阵就行。"

### 10.5 迁移到整车 CAN(1700帧/s)的延伸思考

- **批量收帧**:1700帧/s ≈ 每0.6ms一帧,收包线程应"攒批"处理(如10ms一批 ≈ 17帧),而不是逐帧处理,减少线程切换。
- **按信号更新,按周期发布**:解析线程只写信号槽;业务按固定周期(如10ms)批量读取变化信号,而不是每帧唤醒业务。
- **优先级/去重**:可配置哪些信号需要变化检测(version),哪些需要超时,哪些事件型即时上报。
- **背压保护**:信号槽固定大小,天然抗突发;接收侧可用环形缓冲+丢帧策略,保证最新状态优先。
- **内存/锁**:预分配+单锁批量更新,避免高频 malloc/free 和锁竞争。
