# 04 · 算法抽象层详解(补全理解,展示架构设计能力)

> 本模块不是你的真实产出,但它是本项目**架构最精华**的部分。
> 面试中讲好"算法抽象层"能直接展示你的**面向接口设计能力**。
> 对应代码:`mdlSafety/alg_abstract_api_st/`

## 一、模块职责总览

**alg_abstract_api_st** 解决的核心问题:**对接多家算法厂商,业务层不感知厂商差异**。

| 文件 | 说明 |
|---|---|
| `include/alg_abstract_api.h` | 统一对外接口声明(所有业务调它) |
| `include/alg_abstract_data_st.h` | 统一数据结构(厂商无关) |
| `src/alg_api_ARC.cpp` | 虹软(ArcSoft)实现(1592行) |
| `src/alg_api_MOTOVIS.cpp` | 魔视(Motovis)实现(589行) |
| `include_arcSdk/` | 虹软SDK头文件 |
| `include_motovisSdk/` | 魔视SDK头文件(含联咏NT接口) |

### 编译切换(面试必答)

```makefile
SAFETY_ALGORITHM=arc     # → -DSAFETY_ALGORITHM_ARC → 编alg_api_ARC.cpp
SAFETY_ALGORITHM=motovis # → -DSAFETY_ALGORITHM_MOTOVIS → 编alg_api_MOTOVIS.cpp
```

两个厂商实现**同名函数**,通过宏二选一编译,业务层代码完全不用改。

### 面试话术示例

> "算法抽象层是我的项目里最能体现架构设计的一个模块。它把虹软、魔视两家算法厂商封装成统一的接口,对外提供激活、初始化、逐帧检测、参数设置、事件转换这些能力。
> 业务层永远只看到一套数据结构——比如报警事件统一叫 DmsResult_t、AdasResult_t,不会出现虹软或魔视的私有结构。
> 换算法厂商时,只需要在抽象层内部新写一个实现文件,编译宏切一下,整个业务代码一行不改。"

### 冷却机制(ALG_InCoolDown)

```cpp
// g_cooldown: 模块 → 事件 → {冷却秒数, 上次触发时间}
// 基于上电时间 tool_getCurrentTimeSecondsFromPowerOn()
// 距上次触发 >= 冷却时间 → 返回0(可上报),否则返回1(冷却中忽略)
// 目前只覆盖DMS/ADAS,BSD无冷却条目(返回-1不过滤)
```

> 面试点:冷却机制的意义——**防止同一事件在短时间内反复上报刷屏平台**,如DMS闭眼冷却20s、驾驶员异常180s、镜头遮挡300s。

## 五、虹软实现详解(alg_api_ARC.cpp)— 掌握流程

### 5.1 初始化流程(ALG_handleInit)

```cpp
1. ALG_getActivateStatus() 确认模块已激活
2. 组装 ARC_InitModParam_t(哪些模块、模型路径 /mnt/syscfg/safety/arc_safety_model)
3. ARC_CreateHandle(...) 创建算法句柄
4. 按模块调参数加载:
   ALG_DMS_ParaLoad()  /  ALG_ADAS_ParaLoad()
   (BSD的ParaLoad调用被注释"多通道初始化逻辑待考虑")
```

### 5.2 DMS检测流程(ALG_DMS_Detect)

```cpp
1. 从 ImageInfo_t 取YUV数据地址(只拷指针,不拷数据!)
2. 填 ARC_DMS_InputImage_t(nv21格式)
3. ARC_DMS_Detect(handle, input, &arcDmsRst)
4. 结果转换:
   arcDmsRst.alarmMask → DmsResult_t.alarmMask
   arcDmsRst.faceRect → FaceInfo_t
   arcDmsRst.distractType → DMS_Distract_t
5. 返回给上层
```

### 5.3 ADAS检测流程(ALG_ADAS_Detect)

```cpp
1. 同样灌YUV → ARC_ADAS_Detect
2. 结果转换:
   车道偏离: departureType(0无/1左/2右)
   前碰/行人: objInfos[8](目标类型/矩形/距离/速度/TTC)
3. ⚠️ 代码问题:用static结果缓冲,多线程/多路调用会互相覆盖
```

### 5.4 BSD检测流程(ALG_BSD_Detect)

```cpp
1. args参数传入bsd序号(0~3)
2. 按安装方式分派:
   PARALLEL平行线 → ARC_BSD_PARALLEL_Detect
   OVERLOOK俯视 → ARC_BSD_OVERLOOK_Detect
3. 结果:BsdResult_t.alarmMask + alarmDetailVec(行人/车辆,危险级别)
```

### 5.5 激活流程(ALG_activateSDK)— 面试重点

```cpp
在线激活:
  ARC_ActiveEnvParam_t envParam;
  envParam.storagePath = 激活文件目录(上层传入,默认/mnt/syscfg/safety);
  envParam.IMEI = imei;
  ARC_Activate(appId, appSecret, modParam, &envParam);
  // 虹软机制:首次在线激活后,授权信息缓存到storagePath
  // 之后每次启动,ARC_Activate先查本地缓存,有则直接授权(无需联网)

离线激活:
  ⚠️ 设计上不可达(函数体直接return -1)
  // 虹软没有独立license文件机制,靠"首次在线+本地缓存"
```

> 面试话术:"算法激活是虹软的在线激活模式——设备首次联网激活,虹软把授权信息缓存到本地文件,之后启动就不用联网了。我理解这个机制后,发现激活函数的返回值处理有个坑:激活失败时函数还是返回0,上层会误判成功。这类问题我在优化时都会关注。"

## 七、魔视实现对比(alg_api_MOTOVIS.cpp)— 展示你懂两家厂商

| 维度 | 虹软(ARC) | 魔视(MOTOVIS) |
|---|---|---|
| 检测方式 | 同步调用 ARC_DMS_Detect 等 | **回调模式**:注册 `_ALG_DMS_ResultProcFunc`,算法内部结果回调 |
| 帧结构 | ImageInfo_t 通用结构 | 直接用联咏 `HD_VIDEO_FRAME`(NT耦合) |
| 事件 | 掩码位匹配 | 回调里 eventResult->nEventType 位匹配 |
| 模型 | arc_safety_model(.bin) | motovis_safety_model |
| 依赖 | libArcSoftVisDrive* | 静态库 + opencv |

### 魔视回调模式示例(面试可讲)

```cpp
// 注册回调给魔视算法,算法出结果自动回调
void _ALG_DMS_ResultProcFunc(int chn, ObjectTrackEventResult* result, ...) {
    int alarmMask = result->nEventType;
    const vector<unsigned int>& eventVec = ALG_eventVec(ALG_MODULE_DMS, alarmMask);
    for(auto ev : eventVec)
        Alarm_SafetyEvent(ALG_MODULE_DMS, ev, NULL);  // 直接进报警链路
}
```

> 面试点:同一套抽象接口,虹软是"拉模式"(同步调用拿结果),魔视是"推模式"(回调),抽象层把两种模式都统一成了 `ALG_xxx_Detect` 接口对外。这就是抽象的价值。

## 九、面试问答准备(本模块)

**Q1:为什么做算法抽象层?**
> 因为项目可以对接虹软和魔视两家算法厂商,而且可能后续还会换。如果不抽象,业务代码会到处是厂商SDK的调用和数据结构,换厂商等于重写业务。抽象后,业务只依赖统一接口,厂商差异全部收口在抽象层内部,换厂商就是换一个实现文件、改一个编译宏。

**Q2:统一数据结构怎么处理厂商差异?**
> 定义厂商无关的通用结构(报警类型枚举、结果结构、标定结构),厂商实现内部做映射转换。差异大的地方留特例字段,比如魔视直接用联咏帧结构,通用ImageInfo_t里预留了motovisFrame指针。

**Q3:报警事件怎么统一?**
> 每家厂商的事件掩码定义不同,抽象层维护映射表,检测结果出来后按位匹配转换成通用事件,业务层永远处理通用事件。一次触发可能命中多个事件(比如同时抽烟+分心)。

**Q4:冷却机制的意义?**
> 防止同一事件短时间重复上报刷屏。比如DMS闭眼20秒内不重复报,镜头遮挡300秒,保证平台侧报警质量和网络流量可控。

**Q5:标定流程?**
> 数据库/App设置标定参数 → 参数层存SafetyParaWithCalib_st → 算法层取AdasCalib_t/BsdCalib_t → 逐字段转换厂商结构 → 调用厂商标定接口。注意"设置未生效,需初始化后加载"的时序。

**Q6:激活机制?**
> 虹软在线激活:首次联网ARC_Activate授权,授权信息缓存到本地目录,之后启动离线可用。通过激活文件是否存在判断是否需要连激活平台。
