### 必考知识点（点击直达对应页面）

- [OTA 升级链路全流程（排查视角）](#/05-auto?goto=OTA 升级链路全流程（排查视角）)——云端下发 → 下载（断点续传）→ 完整性校验 → 验签 → 解密 → UDS 刷写 → 版本校验 → 提交/回滚，排查时按"卡在哪一环"定位，每阶段有独立日志与状态码；`面试怎么挂钩`：这就是我梳理的链路本身，也是排查时的分段地图。
- [断点续传与状态持久化](#/05-auto?goto=断点续传与状态持久化)——下载和刷写做成状态机，把阶段、字节偏移、块校验值持久化到 NVRAM/文件，崩溃重启后从断点恢复，状态文件用"临时文件 + 原子改名 + fsync"写入；`面试怎么挂钩`：市场"升级到一半断电"类问题，先查 NVRAM 里的 phase 和 offset 是否有效。
- [UDS 诊断服务总览（ISO 14229）](#/05-auto?goto=UDS 诊断服务总览（ISO 14229）)——UDS 是应用层诊断协议，经 CAN TP 承载；核心服务 10 会话控制、27 安全访问、34/36/37 传输、负响应统一为 7F + SID + NRC；`面试怎么挂钩`：刷写失败时抓 UDS 报文看 NRC（0x33/0x31/0x78）即可定位环节。
- [UDS 安全访问 27](#/05-auto?goto=UDS 安全访问 27)——奇数级别请求 seed → ECU 返回随机 seed → 回发 key → 校验通过解锁写权限，防暴力破解靠 seed 每次不同 + 尝试次数上限；`面试怎么挂钩`：刷写前安全访问失败是常见故障点，先看 0x27 应答的 NRC 判断是 key 错还是超次数锁定。
- [34/36/37 固件下载流程](#/05-auto?goto=34/36/37 固件下载流程)——0x34 请求下载（声明地址与长度）→ 0x36 按块传数据（块序号 1~255 回绕）→ 0x37 请求退出传输，刷写后校验完整性，失败整包作废；`面试怎么挂钩`：刷写环节报错时按 34→36→37 分段看是建立会话、传块还是收尾失败。
- [CAN TP（ISO 15765-2）](#/05-auto?goto=CAN TP（ISO 15765-2）)——单帧最多带 7 字节数据，超过用首帧声明总长、连续帧传数据、流控帧控制节奏，接收端按 PCI 重组完整报文；`面试怎么挂钩`：UDS 刷写底层就是 CAN TP 多帧传输，流控时序不对会导致刷写超时失败。
- [HTTPS 工作原理与加密基础](#/04-net?goto=HTTPS 工作原理与加密基础)——HTTPS = HTTP + TLS，先校验证书确认服务器身份，再用非对称加密安全交换密钥、之后全部走对称加密；`面试怎么挂钩`：OTA 下载走 HTTPS，与升级包 SM2/RSA 验签、SM4/AES 解密是同一套"非对称换密钥 + 对称加密"思路。
- [MQTT 协议（重点）](#/04-net?goto=MQTT 协议（重点）)——MQTT 基于 TCP 的发布/订阅协议，QoS 0 至多一次、1 至少一次、2 恰好一次；keepalive 心跳感知掉线，遗嘱消息在异常掉线时代发，断线重连配合指数退避；`面试怎么挂钩`：云端下发升级任务常走 MQTT，任务丢失/掉线类问题先看 QoS 与心跳是否生效。
- [22. FLASH 与 RAM 的区别](#/12-embedded?goto=22. FLASH 与 RAM 的区别)——FLASH 非易失、读快写慢、按扇区擦除后再写、擦写寿命有限；RAM 易失、速度快；频繁写的数据避免直接写 FLASH；`面试怎么挂钩`：固件存 FLASH、进度存 NVRAM，理解分区与寿命才能解释"刷写即大写入"对 eMMC 的影响。

### 面试追问 Q&A

- **Q：** 升级失败一般分几类？
- **A：** 四类：下载失败（网络/断点）、验签失败（包损坏/证书）、刷写失败（通信/时序）、版本校验失败；排查时按链路分段定位。
- **Q：** 断点续传怎么实现？
- **A：** 下载进度和状态持久化到 NVRAM，重启后从断点继续，不用重头下载。
- **Q：** 升级状态机有哪些状态？
- **A：** 空闲、检查、下载、暂停、升级、预安装等，崩溃后能从持久化的状态恢复。
- **Q：** 为什么刷写要 34/36/37？
- **A：** 34 请求下载建立会话，36 传输数据，37 请求退出结束传输，配合 27 安全访问解锁刷写权限。
- **Q：** 你在 OTA 里的角色是什么？
- **A：** 我是维护排查角色：模块由同事开发，我负责排查市场 OTA 升级失败问题，梳理链路、抓日志定位是哪个环节失败并给出处理建议，不负责模块开发。
- **Q：** 怎么快速定位是哪个环节失败？
- **A：** 先看升级状态码与阶段日志 → 下载失败看网络/磁盘/续传点；刷写失败抓 UDS 报文看 NRC；校验失败比对包哈希、确认分区是否写对。
- **Q：** 升级包为什么要验签解密？
- **A：** 防篡改防注入——SM2/RSA 验签保证包来源可信，SM4/AES 解密防止传输与包体泄露，刷写前必须通过。
- **Q：** 升级一半断电会不会变砖？
- **A：** 不会——状态机 + NVRAM 持久化 + 回滚机制，重启后从断点继续或回退旧版本。
