### 项目一句话

国产化终端上，用多线程 + 生产者消费者 + CRC32 实现了 GNSS 模块串口固件升级。

### 项目 STAR

**背景**：国产化高性能终端需要支持 GNSS 模块固件在线升级；串口通信容易丢数据、阻塞，升级失败会直接影响终端可用性。

**我的职责**：独立设计并实现升级系统，保证传输可靠、升级可恢复。

- 串口通信 + 协议解析
- 多线程架构，生产者-消费者模型分离串口监听与协议处理，避免阻塞和丢帧
- CRC32 校验保障每包完整性
- 升级状态机管理流程：失败重试、异常恢复（断电续刷/回退）

**技术亮点**：

- 生产者-消费者模型解耦串口收发与协议处理，不丢包
- CRC32 逐包校验 + 重发/回退机制，防"半砖"
- 升级状态机 + 断电续刷/回退，升级可恢复

- [9. 串口通信](#/12-embedded?goto=9. 串口通信)——UART 是异步串行通信，收发双方必须约定相同波特率；TTL 板内短距离、RS-232 抗干扰点对点、RS-485 差分多点半双工；`面试怎么挂钩`：GNSS 模块定位数据与固件升级都走串口协议解析（NMEA 文本帧 + 厂商升级帧）。
- [生产者-消费者问题（手写伪代码）](#/03-os?goto=生产者-消费者问题（手写伪代码）)——用"互斥锁 + 两个条件变量"实现有界缓冲，满等 not_full、空等 not_empty，条件判断用 while 防虚假唤醒；`面试怎么挂钩`：串口收包快、协议处理慢，顺序处理会阻塞丢帧，生产者-消费者解耦后不丢数据。
- [同步互斥全家桶对比（互斥锁/信号量/条件变量/自旋锁/读写锁）](#/03-os?goto=同步互斥全家桶对比（互斥锁/信号量/条件变量/自旋锁/读写锁）)——互斥锁独占且必须由持有者解锁、信号量是计数器、条件变量必须配互斥锁、自旋锁忙等不睡眠、读写锁读多写少提升并发；`面试怎么挂钩`：升级系统多线程共享接收队列，互斥锁保护 + 条件变量通知，避免竞态和忙等。
- [环形缓冲区（加锁版与无锁版思路）](#/02-c?goto=环形缓冲区（加锁版与无锁版思路）)——环形缓冲区用 head/tail 指针 + 模运算实现 FIFO，留一个空位区分空/满，SPSC 场景可无锁（先写数据再更新指针 + 内存屏障）；`面试怎么挂钩`：串口接收 FIFO 就是环形缓冲区，满了按策略暂停读取或丢弃旧包并告警。
- [位操作（置位/清位/翻转/统计 1 的个数）](#/02-c?goto=位操作（置位/清位/翻转/统计 1 的个数）)——| 置位、&~ 清位、^ 翻转、& 判断，统计 1 的个数用 Kernighan 算法 x &= (x-1)；`面试怎么挂钩`：CRC32 逐包校验本质是位运算，FLASH/串口寄存器配置同样靠位操作。
- [OTA 升级链路全流程（排查视角）](#/05-auto?goto=OTA 升级链路全流程（排查视角）)——云端下发 → 下载（断点续传）→ 完整性校验 → 验签 → 解密 → UDS 刷写 → 版本校验 → 提交/回滚，排查时按"卡在哪一环"定位；`面试怎么挂钩`：GNSS 固件升级是同一套升级链路在串口通道上的落地，讲流程时能类比整车 OTA。
- [10. 定时器](#/12-embedded?goto=10. 定时器)——定时器 = 计数器 + 时钟源，计数到 0 触发中断，用于定时调度、超时检测、看门狗、心跳上报；`面试怎么挂钩`：升级包的接收超时、重发计时、看门狗保活都靠定时器。

### 面试追问 Q&A

- **Q：** 为什么用生产者-消费者模型？
- **A：** 串口收包快、处理慢，顺序处理会阻塞导致丢帧；生产者和消费者解耦后，收包线程只管入队，处理线程慢慢消化，不丢数据。
- **Q：** 缓冲区多大？满了怎么办？
- **A：** 【待补充：具体数值，如 64KB】；满了按策略暂停读取或丢弃旧包并告警，保证不覆盖未处理的包【按实际】。
- **Q：** CRC32 校验出错怎么办？
- **A：** 重发该包；重发超限则报错并进入回退流程，保证终端不变成"半砖"。
- **Q：** 升级过程中掉电怎么办？
- **A：** 状态机持久化升级进度，异常恢复支持断电续刷或回退，重启后从断点继续或回到旧版本。
- **Q：** 多线程之间怎么同步？
- **A：** 互斥锁保护共享队列，条件变量/信号量做生产者-消费者通知，避免竞态和忙等。
- **Q：** 串口为什么会丢数据？
- **A：** 串口是异步的，接收缓冲溢出、处理不及时、波特率不匹配、中断丢失都会丢；所以用中断/FIFO 收字节 + 消费者线程及时取走。
- **Q：** 升级状态机有哪些状态？
- **A：** 空闲、接收中、校验中、刷写中、完成/失败【按实际列】；关键状态和进度持久化，重启后按状态恢复。
