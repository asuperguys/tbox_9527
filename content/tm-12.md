## 卡片8:三急物理模型(面试深度天花板,[21 文档](#/tm-21)+代码)

```
现网缺陷→改进:
  无滤波      → 一阶低通(截止~5Hz:运动<2Hz,颠簸>10Hz)
  重力基准固定 → 互补滤波姿态估计 + 减去重力投影(g·sin pitch/roll)
               = 真实纵向加速度 ax_real
  只看角速度   → 横向加速度 = 车速×角速度(v×ωz)双判据
  瞬时触发     → 时间窗口(2s)+ 占空比(70%)+ 滞回
  无耦合抑制   → 转弯中抑制纵向判定 + 车速交叉验证
关键物理量:急转弯危险度 = v×ωz;刹车点头2~3°≈0.5m/s² 必须补偿
落地:three_urgent_physics.cpp(独立实现+单测7用例+宏SAFETY_USE_PHYSICS_3URGENT可选)
工程坑:M_PI非标准宏(用TU_PI)/姿态初值收敛/判定互斥(急加减独立统计+触发互斥,修过漏报bug)
```

## 卡片9:CAN信号级重构(我的实战优化)

```
问题:字段误清(整体覆盖) / 数据陈旧(无超时) / 收包阻塞(业务同步跑) / 日志风暴
方案:信号注册表+信号槽+超时监控(500ms)+变化检测(version)+批量更新(单锁)
     解析只写槽,业务按需读(有效性判断),三急100ms节流,日志5s节流
风险控制:对外接口全不变 + 独立单测 + 原文件备份
迁移宇通1700帧/s:解析/业务解耦 + 攒批(10ms≈17帧) + 周期发布 + 分级超时
本质:AUTOSAR COM 信号模型 = 从"逐帧事件驱动"到"信号状态管理"
超时双保险:惰性判断(读时,保正确) + 周期线程(1s,保及时,可选/方案B)
```

## 卡片10:整车CAN 1700帧/s 方案(宇通杀手锏,[22 文档](#/tm-22))

```
量级:1700帧/s ≈ 0.59ms/帧,处理预算<0.5ms,500kbps利用率~27%
难点:处理次数多/周期+事件混合/数据陈旧/抖动突发
分层:接收(SocketCAN+内核过滤) → 解析(攒批10ms≈17帧,单锁批量)
     → 信号层(CanSignalMgr) → 消费(10ms周期+version只处理变化)
关键信号:制动/转向不攒批,独立高优先级队列即时处理(<1ms)
性能账:攒批后 1700→100次/s,单帧解析<10μs,接收CPU<5%
可靠性:环形缓冲(突发吸收) + 信号超时(分级) + 关键信号优先
DBC对接:报文矩阵→生成注册表代码,改DBC重新生成
与天迈关系:内核(信号管理)直接复用,外层按场景增强(攒批/优先队列/缓冲)
```
