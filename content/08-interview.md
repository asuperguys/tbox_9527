## 自测题库与面试话术

> 使用方法：先关掉答案自己答一遍（录音效果更佳），答不上来或结巴的题记进错题本，考前只刷错题；每道题参考要点不是标准答案，而是"能直接说出口"的话术骨架，用自己的项目经历填肉。

### 自我介绍模板

**30 秒版：**
面试官好，我有 5 年嵌入式软件开发经验，一直做车载方向。前两年做公交智能终端，负责底层驱动和通信协议；后来转向主动安全产品，接触了摄像头融合和 ADAS 相关控制逻辑；最近两年在宇通做 TBOX，负责车联网通信和整车数据上报。技术栈主要是 C 语言、Linux 环境开发，熟悉 CAN 总线和 MQTT 协议。这次求职想做嵌入式软件岗，方向是车联网或车载终端，希望能把这几年的车载经验延续下去。

**1 分钟版：**
面试官好，我有 5 年嵌入式软件经验，专注车载领域。我的经历分三段：第一段做公交智能终端，负责 Linux 环境下 C 语言开发，从 boot 到应用层，写驱动、调串口，把整个产品的软件流程走通了；第二段做主动安全产品，接触了毫米波雷达和摄像头数据融合、报警策略这类业务，学会了在多模块协同下做状态机设计和问题定位；第三段在宇通做 TBOX，这是我最完整的车联网经历——负责 CAN 报文解析、远程诊断、MQTT 上云上报，也做过 OTA 升级。我自己对车载协议栈和可靠性要求比较熟悉，平时也喜欢复盘代码和写排查文档。这次看中的是咱们这个嵌入式软件岗，跟我的 TBOX 经验完全对口，希望能有机会深入聊聊。

### 离职原因与求职动机话术

> **问"为什么离职"（最常见）：** 要点：客观原因 + 成长诉求，不贬低前公司。话术："前公司业务稳定但项目趋于维护，新东西少了；我想找更能深入做产品迭代、技术上有成长空间的平台，所以出来看看。"绝不提薪资第一、绝不抱怨加班或领导。

> **问"为什么来我们公司"：** 要点：先做功课（公司做什么产品、和你的交集），用"匹配"说话。话术："咱们公司做车联网/智能座舱方向，和我 TBOX 的经验正好对口，我看重的是一来产品有量产压力、能打磨可靠性，二来团队有完整的研发流程，我能把宇通的经验直接复用并继续成长。"

> **问"为什么离开宇通/大平台"：** 要点：强调稳定性之外的进取心，避免显得"待不住"。话术："宇通让我把 TBOX 从 0 到 1 做完并量产，该学的都学了；我出来不是嫌累，是想在中小团队承担更多、把产品做到车规级，这种深度是我下一步想要的。"

### 期望薪资与谈薪话术

> **先问预算再报价：** 不主动亮底价，反问："咱们这个岗位的预算范围大概是多少？方便我对照一下。"让 HR 先给区间，你再定位。

> **报区间而非单一数字：** 用"期望 15k 左右，具体看整体 package"这类弹性表述，区间下限是你可接受值，上限略高于理想值，留谈判空间。

> **郑州行情参考：** 郑州嵌入式软件 5 年经验大体在 13-18k 之间，视公司规模与加班情况浮动；报 15k 左右是合理锚点，低于 13k 要结合福利、公积金和成长性综合判断。

> **拿到 offer 再谈细节：** 薪资、年终、公积金基数、加班补贴都等有 offer 了再逐项确认，不要在初面纠缠；拿到 offer 后"谢谢，我回去考虑一下，明天回复"，永远不现场答应。

### 技术面应答原则

1. **先讲结论，再展开细节：** 开头一句话给答案（"会，用信号量+互斥锁"），再讲为什么、怎么用，避免面试官听半天不知道你要说啥。
2. **用项目挂知识点：** 每个八股答案尽量落到自己的项目上（"CAN 丢帧我们排查过，当时是……"），既显真实又能把话题引向自己熟悉的战场。
3. **不会就说排查思路：** 不会的题不装懂，说"这块我平时用得少，但按我的思路会先这样定位……"，把"不会"变成"展示解决问题的框架"。
4. **手写题先讲思路再动笔：** 先口述算法思路、复杂度和边界条件，确认思路正确再写代码，比闷头写完错了强。
5. **没把握的细节主动缩小范围：** 明确说"我熟悉 A 部分，B 部分只是了解"，引导面试官深挖你的强项。
6. **回答带数字和场景：** "大概 3 毫秒""几百台车同时上报"这类具体数字比"很快""很多"有说服力得多。

### 自测 20 题

- [ ] 1. volatile 关键字的作用？什么时候必须用？（硬件寄存器、中断/多线程共享变量；防编译器优化，每次从内存读）
  > 参考答案要点：告诉编译器该变量可能被外部意外修改，禁止优化进寄存器，每次读写都走内存；典型场景是寄存器映射、中断里修改的全局标志。
- [ ] 2. static 关键字有哪些用法？（修饰局部变量、全局变量、函数）
  > 参考答案要点：局部 static 延长生命周期、只初始化一次；全局 static 限定了文件作用域；static 函数只在本文件可见，防止命名冲突。
- [ ] 3. 指针和数组的区别？数组名什么时候退化成指针？
  > 参考答案要点：数组是固定内存块、有大小概念，指针是存地址的变量；sizeof 结果不同；数组名作为函数参数、参与运算时退化为首元素指针。
- [ ] 4. 结构体内存对齐规则是什么？如何避免 padding 浪费？
  > 参考答案要点：成员按自身对齐值偏移，结构体总大小是对齐值的整数倍；按成员大小从大到小排列可减少 padding；通信协议报文用 __attribute__((packed))。
- [ ] 5. 什么是野指针、内存泄漏？如何排查内存泄漏？
  > 参考答案要点：野指针是未初始化/已 free 的指针；泄漏是 malloc 后没 free；排查用 valgrind、ASan，或自己封装 malloc/free 统计计数。
- [ ] 6. 进程和线程的区别？为什么嵌入式里常用线程？
  > 参考答案要点：进程有独立地址空间、开销大；线程共享地址空间、切换快；嵌入式资源有限，用线程省内存且便于共享数据，配合锁同步。
- [ ] 7. 互斥锁和信号量有什么区别？怎么选？
  > 参考答案要点：互斥锁是"谁持有谁释放"的排他锁，用于保护临界区；信号量是计数资源，用于生产者消费者、任务同步；保护共享数据用互斥，任务间通知用信号量。
- [ ] 8. 死锁产生的四个必要条件？如何避免？
  > 参考答案要点：互斥、占有且等待、不可剥夺、循环等待；避免方法是固定加锁顺序、一次性申请所有锁、用超时加锁，杜绝嵌套锁交叉。
- [ ] 9. 你用过哪些 IPC 方式？各适合什么场景？
  > 参考答案要点：共享内存+信号量（快，大数据）、消息队列（解耦、可靠）、socket（跨设备）、信号（异步通知）；TBOX 里模块间常用共享内存和消息队列。
- [ ] 10. TCP 三次握手、四次挥手过程？为什么挥手要四次？
  > 参考答案要点：握手 SYN/SYN-ACK/ACK 确认双方收发能力；挥手因为半关闭，FIN/ACK、FIN/ACK 两次独立关闭，所以四次；TBOX 上 MQTT 长连接依赖 TCP 保活。
- [ ] 11. TCP 粘包问题是什么？怎么解决？
  > 参考答案要点：TCP 是字节流无消息边界；用固定长度、长度字段+包头或特殊分隔符解决；MQTT 协议本身有固定头+剩余长度字段，天然解决。
- [ ] 12. UDP 和 TCP 怎么选？车辆上报场景用什么？
  > 参考答案要点：TCP 可靠有序适合控制指令，UDP 低延迟适合实时状态；车辆 GPS 高频上报可用 UDP+应用层重传兜底，降低服务器连接压力。
- [ ] 13. MQTT 的 QoS 0/1/2 区别？QoS1 怎么保证不丢？
  > 参考答案要点：0 至多一次、1 至少一次（PUBACK 确认+重发）、2 恰好一次（四步握手）；QoS1 靠 broker 存储消息+客户端重发，但可能重复，靠 msgId 去重。
- [ ] 14. CAN 总线帧有哪几种类型？标准帧和数据帧结构？
  > 参考答案要点：数据帧、远程帧、错误帧、过载帧；标准帧 11 位 ID，含 SOF、仲裁场、控制场（DLC）、数据场、CRC、ACK；扩展帧 29 位 ID。
- [ ] 15. CAN 波特率怎么计算？位时序有哪些段？
  > 参考答案要点：波特率 = 外设时钟 / (预分频 × 总位时间)；位时间分同步段、传播段、相位缓冲段 1/2，采样点一般设在 75%-87.5%，我们项目用 500k 采样点 80%。
- [ ] 16. 你项目里 CAN 报文丢帧或错误帧怎么排查？
  > 参考答案要点：先查总线错误计数寄存器、错误状态，区分是单节点还是全网问题；用 CAN 分析仪抓波形看位时序、终端电阻 120Ω、线束长度；软件上检查邮箱/队列是否溢出丢帧。
- [ ] 17. 说说你 TBOX 项目的整体架构？（分层：驱动→协议→应用→云）
  > 参考答案要点：MCU 层收 CAN 整车数据 → Linux 应用层做协议解析、业务逻辑 → MQTT 上云；模块分 CAN 采集、数据网关、远程诊断、OTA、日志；各模块独立进程 + 共享内存/消息队列通信。
- [ ] 18. OTA 升级怎么做？失败怎么回滚？
  > 参考答案要点：A/B 分区双备份，升级写备用分区、校验通过后切换启动标志；失败或校验不过自动回滚到旧分区；升级包要做版本号、CRC 校验和断点续传。
- [ ] 19. 你做过哪些性能或可靠性优化？举一个具体的。
  > 参考答案要点：举真实例子，比如 CAN 采集线程高优先级 + 双缓冲防丢帧；或 MQTT 断线重连用指数退避 + 本地缓存补传；要讲清"问题→方案→量化结果"。
- [ ] 20. 讲一个你线上排查过最难的 bug，过程怎么样的？
  > 参考答案要点：用 STAR 讲：现象（车机偶发重启/丢数据）→ 定位（复现、打日志、二分法、查 core dump）→ 根因（野指针/资源竞争/时序）→ 修复与回归验证；突出排查方法和工程严谨性。

### 行为面试常见问题

- [ ] 你项目中遇到最大的技术挑战是什么？怎么解决的？
  > 应答要点：选一个真实攻坚案例，讲清背景、难点、你做了什么、结果量化（如丢帧率从 x% 降到 0）；突出主动性和复盘。
- [ ] 和同事/产品/测试意见不一致时怎么处理？
  > 应答要点：先对齐目标而非立场，用数据说话、给出可选方案；表述"我坚持的是基于数据的方案，也愿意验证对方的假设"，体现合作不固执。
- [ ] 手上同时多个任务、需求又急，怎么安排？
  > 应答要点：按影响面排序 + 主动暴露风险：先评估每个任务的紧急度和阻塞面，把"会影响联调/产线"的排前，忙不过来会提前同步 leader，不闷头硬扛。
- [ ] 为什么离职？空窗期在做什么？
  > 应答要点：离职用"客观原因+成长诉求"框架；空窗期说复盘、补课、复盘项目文档和刷题，展示状态在线、目标明确。
- [ ] 你带过人或者指导过新人吗？
  > 应答要点：有就讲怎么拆任务、怎么 review 把关；没有就讲怎么帮新人排查问题、沉淀文档，突出分享意愿和工程习惯。
- [ ] 说说你的优缺点？
  > 应答要点：优点给两个和工作强相关（排查问题有方法、文档习惯好）；缺点给一个真实但可控的（如"以前写代码重实现不重抽象，后来通过 review 和学习改进了"），并说明在改进。
- [ ] 未来 3-5 年职业规划？
  > 应答要点：短期（1 年）熟悉业务独当一面，中期（2-3 年）成为车载嵌入式方向的技术骨干/模块负责人，长期向系统架构或技术管理发展；落到"持续深耕车载"。
- [ ] 你对加班怎么看？能接受出差/驻场吗？
  > 应答要点：不直接表忠心也不抗拒：表示理解项目节奏、以结果为导向，遇到紧急版本可以顶；同时反问加班强度和团队现状，把话题引向客观信息。
