## 二、算法喂数据线程(Task_BlockedFeedData)— 多线程面试核心!

### 位置:safety_task_run.cpp:165

### 线程完整流程(背下来)

```cpp
void* Task_BlockedFeedData(void* args):
  // ===== 启动阶段 =====
  1. malloc yuv数据缓冲(memDataSize)
  2. 等待算法激活: while(!(ALG_getActivateStatus() & (1<<algModule))) sleep 500ms
  3. 等待算法初始化: while(!ALG_isAlreadyInited()) sleep 500ms
  4. 等待AV共享内存就绪: while(shareMem_videoMemIsExist(...)) sleep 500ms
  5. shareMem_videoMeminit(chn)  // 映射共享内存

  // ===== 主循环 =====
  while(true):
    - 任务结束检查(taskIsEnd → break)
    - 更新车辆状态: carStatus.update(devData_getSpeed(), devData_getTurnSignal(), 0)
    - 速度无效(<=0) → usleep(20ms) 继续(不浪费CPU)
    - 取一帧YUV: VideoData_blockedGetOneFrameYuv420(chn, yuvData, size, counter)
    - 加锁(feedInfo->lock())  // 防止参数修改/去初始化崩溃
    - ALG_updateDrivingStatus(carStatus)  // 更新车辆状态给算法
    - 帧率统计: 周期内帧计数 + 单帧耗时
    - 组 ImageInfo_t → feedInfo->ALG_Detect(&img, pts, result, arg)  // 灌算法!
    - 解锁(feedInfo->unlock())
    - ret<0 → Alarm_updateAlgRunStatus(module, ret) 继续
    - ALG_eventVec(module, parseResult())  // 结果掩码→通用事件
    - 遍历事件 → Alarm_SafetyEvent(module, event, result)  // 转交报警处理!
```

### 面试要点

1. **多线程模型**:每个算法模块一个线程,互不阻塞;DMS/ADAS/BSD1/BSD2最多4个算法线程并行。
2. **启动同步**:严格等待"激活→初始化→共享内存"三个就绪条件,避免空转和崩溃。
3. **取帧同步**:共享内存+计数器,AV写AI读,文件锁保护。
4. **性能控制**:速度≤0不计算、usleep让CPU、speedLimit速度区间控制(TODO)、帧率统计反馈。
5. **锁的意义**:计算期间持锁,防止参数线程改参数/释放算法导致崩溃。

### 共享内存取帧细节(adapterApi_cameraData.cpp)

```cpp
// 共享内存文件:/tmp/shareMemChn_N,锁文件:同名+_lock
// 内存布局: [计数器4字节] [YUV数据...]
VideoData_blockedGetOneFrameYuv420(chn, data, memSize, &yuvCounter):
  while(1):
    lock()  // 文件锁
    if(计数器 != yuvCounter):   // 有新帧!
      yuvCounter = 计数器; unlock(); memcpy(data, ...); break;
    unlock(); usleep(5ms)        // 还是旧帧,让出CPU再等
```

## 三、报警处理中心(alarm_process)— 报警业务主体

### 3.1 单例 + 核心入口

```cpp
// 报警事件统一入口(算法线程/外设都调它)
int Alarm_SafetyEvent(unsigned int module, int event, void* info):
  1. 冷却过滤: EventProcess_checkIgnore → ALG_InCoolDown(module, event)
     - 返回1(冷却中) → 忽略退出
     - 返回-1(非法) → 打日志
  2. 生成报警序号: alarm->getAlarmSn()(自增)
  3. 组附件信息: EventProcess_makeUpAppendixStructInfo(module, event, apxInfo)
     - 取算法摄像头通道 → videoChn/snapChn(按位表示通道)
     - snapInterval=3, snapNum=3(抓拍3张,间隔3秒)
     - videoDuration = 数据库配置的录制时长
  4. 通知AV产生附件: EventAction_SendCreateAppendix(module, event, sn, apxInfo, filePrefix)
     - 组 AppendixCreateCmd_t(0x0102协议) → UnixMsg_SendDataToAv(AV_ALARM_APPENDIX)
     - 文件名前缀: "模块事件+BCD时间+sn+车牌号/车辆号"(按配置)
  5. 协议上传:
     天迈: EventProcessTiamaes_UploadEvent → Tiamaes_EventPack → tiamaes_AlarmEventUpload
     苏标: EventProcessJSu808_UploadEvent → SuBiao_eventPack → 送调度上传
  6. TTS播报(泰国项目除外,当前注释): EventAction_ttsAlarmRequest
```

### 4.2 附件全流程

```
1. 报警发生 → EventAction_SendCreateAppendix → 通知AV生成附件(0x0102)
   (AV开始抓拍/录像,存到 /mnt/emmc_log/alarm_appendix/)
2. AV生成完毕 → 回通知(SafetyFunc_AvAppendixCmdProc,unixprotocol AV_ALARM_APPENDIX)
   → 按sn查找队列项 → 填充files列表(文件名/大小/通道/类型)
3. 附件上传线程(天迈TiAdx_BlockedUploadTask / 苏标SuBiaoAdx_BlockedUploadTask):
   - 取队首有效任务 → 等附件生成(≤120秒超时)
   - 校验文件存在,不存在的从任务中剔除
   - 上传失败 → 标记冷却(600秒内不重试) → 尝试下一个
4. 上传成功/超时 → 从队列删除
5. 进程退出前 AlarmAppendix_saveData() 持久化未完成任务(重启后AlarmAppendix_loadData恢复)
```

## 八、面试问答准备(本模块)

**Q1:一个算法报警从产生到上报平台的完整过程?**
> 算法线程每帧调ALG_Detect → 结果转事件 → Alarm_SafetyEvent → 冷却过滤 → 生成流水号 → 通知AV抓拍录像 → 协议层组包0x0201上报平台 → 平台回应答从重传队列删除。同时附件上传线程等AV生成完文件后上传到附件服务器。

**Q2:为什么每路算法一个线程?**
> 不同算法模块(ADAS/DMS/BSD)各自处理一路摄像头,数据独立、节奏独立。如果单线程串行处理,一路算法卡顿会影响其他路;多线程让每路独立跑,也便于单独启停和状态监控。缺点是多线程下算法库调用需要保证线程安全。

**Q3:怎么保证YUV取帧不丢不重?**
> 共享内存头部有计数器,AV每写一帧计数器自增。AI取帧时先看计数器是否变化,变了才拷贝(说明是新帧),没变就等下一轮。这样不会重复处理同一帧,也不会漏帧。

**Q4:算法线程和参数线程怎么同步?**
> 算法计算期间持互斥锁。参数修改/算法重初始化前先锁住,等当前帧算完再操作,避免计算中释放算法句柄导致崩溃。

**Q5:附件上传失败怎么办?**
> 失败进入600秒冷却,期间不重试该任务,先传其他任务;超时任务删除;进程退出前持久化未完成任务列表,重启后继续。双保险保证附件尽量送达。

**Q6:进程退出时怎么收尾?**
> main注册atexit(SafetyTask_release):停所有算法线程(置END状态)→释放算法资源→保存未上传附件信息→退出。

## 九、核心记忆卡(背诵)

```
报警旅程:算法结果→事件转换→冷却过滤→附件请求→协议上报→应答删除→附件上传
附件链路:报警→AV抓拍(0x0102)→AV回通知→上传线程→平台/附件服务器→删除
同步三板斧:启动等激活/初始化/共享内存,计算持锁,计数器判新帧
性能三控制:速度门槛、usleep让CPU、帧率统计反馈
收尾:置END→释放算法→存附件→退出
```
